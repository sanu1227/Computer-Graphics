# 1-15 육면체와 사각뿔 애니메이션: 개발 순서대로 읽는 해설

이 문서는 [1-15.cpp](../1-4/1-4/1-15.cpp)의 완성된 코드를 처음 읽는 사람을 위한 설명이다.

실습 PDF 「지엘3 좌표계 변환 (실습 131415)」 4쪽의 명령을 구현했다. 행렬 합성은 「지엘3 좌표계 변환 1」 25~27쪽, 은면 제거는 29~30쪽의 방식에 연결해서 읽으면 된다.

가장 중요한 흐름은 **키 입력으로 상태 변경, 시간에 따라 숫자 변경, 숫자로 행렬을 만들어 그리기**다. 정점 배열 자체를 매 프레임 수정하는 프로그램이 아니다.

본문의 코드 조각은 원본의 일부다. 전체 실행 코드는 위의 소스 파일에서 확인한다.

## 먼저 실행해 본다

프로젝트는 Debug x64에서 `1-15.cpp`를 빌드하도록 설정했다. 실행 파일 이름은 기존 프로젝트 이름인 `1-4.exe`다.

1. 처음에는 약간 기울어진 육면체가 보인다.
2. `y`를 누르면 전체 도형이 회전한다. 다시 누르면 멈춘다.
3. `r`로 초기화하고 `t`, `f`, `s`, `b`를 하나씩 실행해 본다.
4. `1`, `2`, `4`, `5`를 눌러 여러 면이 함께 움직이는 모습을 본다.
5. `p`를 누르면 사각뿔로 바뀐다. 사각뿔도 `y`로 자전할 수 있다.

| 키 | 동작 | 다시 누르면 |
| --- | --- | --- |
| `h` | 깊이 검사 설정/해제 | 설정 전환 |
| `p` | 육면체/사각뿔 선택 | 다른 도형 선택 |
| `y` | 전체 도형의 y축 자전 | 현재 각도에서 정지/재개 |
| `r` | 모든 상태 초기화 후 육면체 출력 | 초기 상태 유지 |
| `q`, `Esc` | 종료 | 프로그램 종료 |
| `t` | 윗면 중심을 지나는 z축으로 회전 | 현재 각도에서 정지/재개 |
| `f` | 앞면 위 모서리를 기준으로 열기 | 닫기/열기로 방향 전환 |
| `s` | 오른쪽 면의 중심을 지나는 x축으로 회전 | 현재 각도에서 정지/재개 |
| `b` | 뒷면을 중심에서 축소해 없애기 | 원래 크기로 복원/축소 |
| `1` | 이웃한 두 옆면을 공통 모서리 주위로 360도 회전 | 새 이웃 쌍을 골라 다시 시작 |
| `2` | 이웃한 두 옆면을 반대 방향으로 90도 공전시켜 자리 교체 | 새 이웃 쌍을 골라 다시 시작 |
| `4` | 네 옆면을 중앙 y축 주위로 계속 공전 | 원래 위치에서 다시 시작 |
| `5` | 위·아래·앞·뒤 면을 중앙 x축 주위로 계속 공전 | 원래 위치에서 다시 시작 |

`t`, `f`, `s`, `b`, 숫자 명령은 육면체에만 적용된다. 이 과제의 `s`는 옆면 회전이다. 1-14의 초기화 명령과 다르다.

# 1부 데이터를 준비한다

## 1 면마다 정점을 따로 둔다

육면체는 꼭짓점 8개로 만들 수 있지만, 이번에는 면마다 다른 변환을 적용해야 한다. 따라서 같은 위치의 꼭짓점도 면별로 따로 저장한다.

사각형 한 면은 삼각형 두 개다. 면 하나에 정점 6개를 사용한다.

```text
육면체: 6개 면 × 6개 정점 = 36개
사각뿔 옆면: 4개 면 × 3개 정점 = 12개
사각뿔 바닥: 1개 면 × 6개 정점 = 6개
도형 합계: 54개 정점
화면 좌표축: 3개 선 × 2개 끝점 = 6개 정점
전체 합계: 60개 정점
```

`vertices[60][3]`의 두 번째 크기 3은 x, y, z 좌표를 뜻한다. 마지막 6개는 화면에 고정할 좌표축의 끝점이다.

## 2 면 번호와 중심을 정한다

| 면 번호 | 육면체의 면 | 중심 좌표 | 정점 시작 위치 |
| --- | --- | --- | --- |
| 0 | 앞 | `(0, 0, 0.4)` | 0 |
| 1 | 오른쪽 | `(0.4, 0, 0)` | 6 |
| 2 | 뒤 | `(0, 0, -0.4)` | 12 |
| 3 | 왼쪽 | `(-0.4, 0, 0)` | 18 |
| 4 | 위 | `(0, 0.4, 0)` | 24 |
| 5 | 아래 | `(0, -0.4, 0)` | 30 |

중심 좌표는 `faceCenters`에 저장한다. 예를 들어 `faceCenters[4]`는 윗면의 중심이다.

각 좌표가 `-0.4`부터 `0.4`까지이므로 육면체 한 변의 길이는 `0.8`이다. 실제 픽셀 길이가 아니라 도형을 정의하는 좌표 단위다.

## 3 면 색을 따로 보낸다

`faceColors[6][3]`은 각 면의 RGB 색상이다. 한 면을 그리기 직전에 `glUniform3f()`로 셰이더에 전달한다.

```cpp
glUniform3f(colorLocation, faceColors[face][0], faceColors[face][1], faceColors[face][2]);
glDrawArrays(GL_TRIANGLES, face * 6, 6);
```

두 번째 인자 `face * 6`은 그 면의 첫 번째 정점 위치다. 마지막 6은 사용할 정점 개수다.

[조각 셰이더](../1-4/1-4/1-15-fragment.glsl)는 받은 `faceColor`를 그대로 출력한다. 따라서 면 하나가 같은 색으로 채워진다.

# 2부 입력과 시간 흐름을 연결한다

## 4 네 함수의 역할을 구분한다

| 함수 | 하는 일 |
| --- | --- |
| `KeyCallback()` | 눌린 키에 따라 실행 여부와 모드를 바꾼다. |
| `UpdateAnimation()` | 지난 시간만큼 각도와 크기를 바꾼다. |
| `GetFaceTransform()` | 면 하나에 적용할 행렬을 만든다. |
| `DrawScene()` | 전체 도형 행렬과 면 행렬을 합쳐 그린다. |

예를 들어 `t`를 누르면 다음 순서로 진행된다.

```text
KeyCallback(): rotateTop을 true로 바꾼다.
UpdateAnimation(): topAngle을 조금씩 늘린다.
GetFaceTransform(4): topAngle로 윗면의 회전 행렬을 만든다.
DrawScene(): 그 행렬로 윗면을 그린다.
```

키 입력 함수가 직접 정점을 돌리거나 그림을 그리는 것은 아니다.

## 5 실행 여부와 현재 각도는 다르다

```cpp
bool rotateTop = false;
float topAngle = 0.0f;
```

`rotateTop`은 앞으로 계속 회전할지를 나타낸다. `topAngle`은 지금까지 회전한 각도다.

`rotateTop`을 false로 바꿔도 `topAngle`은 그대로 남는다. 그래서 `t`를 다시 누르면 현재 자세에서 멈춘다.

키를 누르고 있을 때 발생하는 `GLFW_REPEAT`는 처리하지 않는다. `GLFW_PRESS`에서만 상태를 바꿔서 실행/정지가 반복되지 않게 한다.

## 6 시간에 비례해서 움직인다

```cpp
float angleStep = rotationSpeed * deltaTime;
```

`rotationSpeed`는 초당 60도이고, `deltaTime`은 이전 프레임 이후 지난 초다.

```text
0.1초가 지났다면: 60 × 0.1 = 6도
0.5초가 지났다면: 60 × 0.5 = 30도
```

계속 회전하는 각도에는 `std::fmod(각도, 360.0f)`를 사용한다. 366도는 6도와 같은 자세이므로 6도로 보관한다.

앞면 열기와 자리 교체는 정해진 각도에서 멈춰야 하므로 나머지 연산을 사용하지 않는다. `std::min()`과 `std::max()`로 범위를 제한한다.

메인 루프는 창 이동이나 디버깅으로 오래 멈춘 경우를 위해 한 프레임의 `deltaTime`을 최대 0.1초로 제한한다. 오래 멈췄다가 한꺼번에 크게 회전하는 현상을 줄인다.

# 3부 회전 중심을 이해한다

## 7 특정 지점을 중심으로 회전한다

원점이 아닌 지점 `center`를 중심으로 돌리려면 다음 순서가 필요하다.

1. 중심이 원점에 오도록 `-center`만큼 옮긴다.
2. 원점에서 회전한다.
3. `center`만큼 옮겨 원래 위치로 돌려놓는다.

행렬을 점에 곱하면 오른쪽부터 적용되므로 코드는 다음 순서로 작성한다.

```cpp
faceTransform = glm::translate(faceTransform, center);
faceTransform = glm::rotate(faceTransform, glm::radians(angle), axis);
faceTransform = glm::translate(faceTransform, -center);
```

수식으로는 `T(center) * R(angle) * T(-center)`다. 첫 번째 줄을 보고 정점이 먼저 `center`만큼 움직인다고 해석하면 순서가 반대가 된다.

`glm::radians()`는 사람이 입력하기 쉬운 도 단위를 GLM이 사용하는 라디안으로 바꾼다. `axis`는 회전축 방향이다.

| 회전축 | `axis` |
| --- | --- |
| x축 | `(1, 0, 0)` |
| y축 | `(0, 1, 0)` |
| z축 | `(0, 0, 1)` |

## 8 전체 자전과 면 변환을 합친다

```cpp
glm::mat4 transform = projection * model * faceTransform;
```

정점에 적용되는 순서는 다음과 같다.

```text
faceTransform: 면을 열거나 회전하거나 축소한다.
model: 전체 도형의 기울기와 자전을 적용한다.
projection: 화면에 표시할 범위로 변환한다.
```

전체 자전 `y`는 도형 중심을 지나는 y축 기준이다. 면을 열어 둔 상태에서 `y`를 누르면 열린 면까지 전체 도형과 함께 회전한다.

시작 기울기는 `startAngleX = 25.0f`, `startAngleY = 30.0f`다. PDF는 시작 각도를 변경할 수 있도록 허용한다.

15번은 기본 코드에 있던 직교 투영을 사용한다. x와 y의 표시 범위는 `-1.8 ~ 1.8`로 넓혔다. 공통 모서리를 중심으로 360도 회전할 때 원래 육면체보다 훨씬 넓은 공간을 지나므로, 움직이는 면이 화면 경계에서 잘리지 않게 하기 위해서다.

# 4부 한 면씩 움직인다

## 9 t: 윗면 중심에서 z축 회전

윗면 번호는 4이고 중심은 `(0, 0.4, 0)`이다. 이 중심을 지나는 z축으로 회전한다.

`rotateTop`이 true일 때 `topAngle`을 늘린다. `GetFaceTransform(4)`는 이 각도로 중심 회전 행렬을 만든다.

**확인:** 윗면 모서리는 움직여도 윗면의 중심은 그대로다. 다시 `t`를 누르면 그 각도에서 멈춘다.

## 10 f: 앞면을 위 모서리에서 열고 닫기

앞면 번호는 0이다. 위 모서리는 y와 z가 모두 0.4인 가로선이다. 모서리의 중점 `(0, 0.4, 0.4)`을 중심으로 x축 회전을 한다.

```cpp
if (openFront)
    frontAngle = std::min(frontAngle + angleStep, 90.0f);
else
    frontAngle = std::max(frontAngle - angleStep, 0.0f);
```

`frontAngle`은 0~90도로 저장한다. 실제 행렬에는 `-frontAngle`을 적용해 앞면이 바깥쪽으로 열리게 한다.

```text
닫힌 앞면의 아래쪽 점: (0.4, -0.4, 0.4)
완전히 열린 뒤의 위치: (0.4, 0.4, 1.2)
위쪽 모서리의 점: 회전 전후 같은 위치
```

열리는 도중 `f`를 누르면 현재 각도에서 닫히기 시작한다. 끝까지 열려면 60도/초 기준 1.5초가 걸린다. 열림 각도 90도는 이번 구현에서 정한 값이다.

## 11 s: 오른쪽 면 중심에서 회전

오른쪽 면 번호는 1이고 중심은 `(0.4, 0, 0)`이다. 이 면에 수직인 x축을 기준으로 회전한다.

전체 육면체 중심에서 공전하는 동작과 다르다. 오른쪽 면의 중심은 그대로 있고, 그 중심 주위로 면의 모서리만 돌아간다.

`rotateSide`가 true일 때 `sideAngle`을 늘린다. `s`를 다시 누르면 현재 각도를 유지하며 멈춘다.

## 12 b: 뒷면을 중심에서 축소하고 복원

뒷면 번호는 2이고 중심은 `(0, 0, -0.4)`다. 중심을 원점으로 옮긴 뒤 크기를 바꾸고 다시 제자리로 옮긴다.

```cpp
faceTransform = glm::translate(faceTransform, center);
faceTransform = glm::scale(faceTransform, glm::vec3(backScale));
faceTransform = glm::translate(faceTransform, -center);
```

| `backScale` | 의미 |
| --- | --- |
| 1 | 원래 크기 |
| 0.5 | 가로와 세로가 각각 절반 |
| 0 | 크기가 0이 되어 사라짐 |

매초 1만큼 크기 값을 줄이거나 늘린다. 1에서 0까지 약 1초다. 크기가 정확히 0이면 `DrawScene()`에서 뒷면 그리기를 건너뛴다.

**확인:** 면이 원점으로 이동하면서 작아지는 것이 아니라, 뒷면의 중심에 그대로 남아 작아져야 한다. 기본 시점에서는 뒷면이 다른 면에 가려질 수 있으므로 `y`로 도형을 돌려 확인한다.

# 5부 두 면과 네 면을 움직인다

## 13 이웃한 두 면을 고른다

옆면 번호는 앞 0, 오른쪽 1, 뒤 2, 왼쪽 3 순서다.

```cpp
firstFace = std::rand() % 4;
secondFace = (firstFace + 1) % 4;
```

가능한 쌍은 `(0,1)`, `(1,2)`, `(2,3)`, `(3,0)`이다. 모두 하나의 세로 모서리를 공유한다.

`% 4` 때문에 3의 다음 번호가 4가 아니라 0이 된다. 실행 시작 때 `std::srand()`로 난수 시작값을 한 번 설정한다.

## 14 숫자 1: 공통 모서리를 기준으로 한 바퀴

선택한 두 면의 중심을 더하면 공유하는 세로 모서리의 중점을 얻는다.

```text
앞면 중심: (0, 0, 0.4)
오른쪽 면 중심: (0.4, 0, 0)
합: (0.4, 0, 0.4)
```

두 면에 같은 중심, 같은 y축, 같은 `twoFaceAngle`을 사용한다. 두 면은 붙어 있는 모양으로 공통 모서리를 중심으로 회전한다.

360도에 도달하면 `twoFaceMode`와 `twoFaceAngle`을 0으로 바꾼다. 한 바퀴가 끝난 상태는 시작 자세와 같으므로 원래 위치에서 정지한다. 초당 60도이므로 약 6초가 걸린다.

**확인:** 모서리 위의 두 끝점은 애니메이션 중에도 같은 위치에 있어야 한다. 다른 네 면은 움직이지 않는다.

## 15 숫자 2: 반대 방향으로 공전해 자리 교체

이번 중심은 공통 모서리가 아니라 육면체 중앙 `(0, 0, 0)`이다.

```cpp
center = glm::vec3(0.0f);
angle = face == firstFace ? twoFaceAngle : -twoFaceAngle;
```

첫 번째 면은 양의 방향, 두 번째 면은 음의 방향으로 돈다. `twoFaceAngle`은 90도까지만 증가한다.

예를 들어 앞면과 오른쪽 면을 골랐다면 다음과 같이 움직인다.

```text
앞면: 중앙 y축으로 +90도 회전해서 오른쪽 면 위치로 이동
오른쪽 면: 중앙 y축으로 -90도 회전해서 앞면 위치로 이동
```

각 면의 색은 그대로 따라간다. 색 배열만 바꾸는 것이 아니라 실제 면의 위치를 바꾼다.

완료 후에도 `twoFaceMode = 2`, `twoFaceAngle = 90`을 유지한다. 모드를 바로 0으로 바꾸면 면들이 원래 자리로 돌아가므로, 교체된 결과를 보여 주려면 최종 변환을 유지해야 한다.

## 16 숫자 4: 네 옆면의 y축 공전

0, 1, 2, 3번 면에 중앙 y축 회전을 적용한다. 위·아래 면인 4, 5번에는 단위 행렬을 반환한다.

단위 행렬은 정점을 바꾸지 않는 행렬이다. 그래서 위·아래 면은 고정되고 옆면 네 개만 움직인다.

`fourFaceAngle`은 계속 증가하며 한 바퀴를 넘으면 0~360도 범위로 돌아온다. `r`이나 다른 면 명령으로 전환할 때까지 공전한다.

## 17 숫자 5: 네 면의 x축 공전

위·아래·앞·뒤 면인 4, 5, 0, 2번에 중앙 x축 회전을 적용한다. x축 양쪽에 있는 오른쪽·왼쪽 면 1, 3번은 고정한다.

90도 회전했을 때 각 면의 중심은 다음 위치에 도착한다.

| 원래 면 | 이동한 위치 |
| --- | --- |
| 앞 | 아래 |
| 아래 | 뒤 |
| 뒤 | 위 |
| 위 | 앞 |

4번 명령과 5번 명령은 회전축과 움직일 면의 집합이 다르다.

# 6부 명령 전환과 그리기 설정을 마무리한다

## 18 여러 명령을 눌렀을 때의 규칙

PDF에 명령 조합의 상세 규칙은 없으므로, 변환 중심이 어긋나지 않게 다음처럼 정했다.

- `y`의 전체 자전은 면 애니메이션과 함께 사용할 수 있다.
- `t`, `f`, `s`, `b`는 서로 다른 면을 다루므로 함께 사용할 수 있다.
- `1`, `2`, `4`, `5`를 누르면 `ResetFaces()`로 면들을 원래 위치에 돌려놓고 새 명령을 시작한다.
- 여러 면 명령 중 `t`, `f`, `s`, `b`를 누르면 여러 면 변환을 초기화하고 해당 명령을 시작한다.
- 사각뿔로 전환하면 육면체 면 애니메이션은 일시 정지한다. 육면체로 돌아오면 보관한 상태에서 이어진다.
- `r`은 면 상태뿐 아니라 전체 자전과 각도까지 초기화하고 육면체를 선택한다. 깊이 검사도 켠다.

`ResetFaces()`와 `ResetObject()`를 구분한 이유가 이것이다. 면 명령을 바꿀 때 전체 도형의 자전까지 초기화할 필요는 없다.

## 19 PDF 방식으로 은면 제거한다

매 프레임 두 버퍼를 함께 초기화한다.

```cpp
glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT);
```

`h`로 바꾼 `hiddenSurface` 값에 따라 깊이 검사를 켜거나 끈다.

```cpp
if (hiddenSurface)
    glEnable(GL_DEPTH_TEST);
else
    glDisable(GL_DEPTH_TEST);
```

깊이 검사를 켜면 겹친 위치에서 가까운 면이 보인다. 끄면 나중에 그린 면이 앞선 면을 덮을 수 있다. 별도의 면 컬링, 보이지 않는 면 선행 그리기, 깊이 보정은 사용하지 않는다.

## 20 셰이더와 프로그램의 연결

### 화면 중앙에 고정된 좌표축

13·14번과 같은 모양으로 x축은 빨강의 오른쪽 위 대각선, y축은 초록의 수직선, z축 표시는 파랑의 오른쪽 아래 대각선으로 그린다.

도형을 그린 뒤에는 `transform`에 단위 행렬을 전달한다. 그래서 전체 도형이나 개별 면이 회전해도 축은 따라 움직이지 않는다. 육면체와 사각뿔 모두 같은 축을 표시한다.

| 축 | 시작 정점 | 정점 개수 | 색 |
| --- | --- | --- | --- |
| x | 54 | 2 | 빨강 `(1, 0, 0)` |
| y | 56 | 2 | 초록 `(0, 1, 0)` |
| z 표시 | 58 | 2 | 파랑 `(0, 0, 1)` |

`glDrawArrays(GL_LINES, 시작 위치, 2)`는 두 끝점을 잇는 선 하나를 그린다. 색은 기존 `faceColor` uniform으로 지정한다.

화면 안내용 선이므로 끝점의 z좌표는 모두 0이다. `h`로 설정한 깊이 검사는 그대로 적용하므로, 가까운 면에 가려지는 부분은 보이지 않을 수 있다.

### 셰이더에서 위치 계산

[정점 셰이더](../1-4/1-4/1-15-vertex.glsl)의 핵심은 다음 한 줄이다.

```glsl
gl_Position = transform * vec4(position, 1.0);
```

`position`은 배열의 원래 좌표다. `transform`은 C++에서 계산한 행렬이다. 마지막에 1을 붙인 위치 표현을 사용하면 이동까지 포함한 4×4 행렬을 적용할 수 있다.

`ReadShaderFile()`은 작업 폴더에서 파일을 찾고, 없으면 소스 파일 옆에서 찾는다. 프로젝트는 빌드한 실행 파일 옆에도 15번 전용 셰이더를 복사한다.

## 23 이해 확인 문제

1. `rotateTop`과 `topAngle`은 무엇이 다른가?
2. 회전 전에 중심을 원점으로 옮기는 이유는 무엇인가?
3. 3번 옆면의 다음 면은 왜 0번인가?
4. 두 면의 자리 교체가 끝나도 모드 2를 유지하는 이유는 무엇인가?
5. 뒷면을 원점 기준으로 축소하면 왜 원하는 결과와 달라지는가?
6. y축 공전과 x축 공전에서 고정되는 면은 각각 무엇인가?

### 답

1. 앞으로 회전을 계속할지와 현재 회전한 각도다.
2. 원하는 지점을 회전의 기준점으로 만들기 위해서다.
3. 옆면 번호가 원형으로 연결되고 `(3 + 1) % 4`가 0이기 때문이다.
4. 최종 90도 변환을 계속 적용해 교체된 위치를 유지하기 위해서다.
5. 면 중심도 원점으로 이동해서 뒷면이 제자리에서 작아지지 않기 때문이다.
6. y축 공전은 위·아래, x축 공전은 오른쪽·왼쪽 면이 고정된다.
