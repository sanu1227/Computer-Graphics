# 1-14 육면체와 사각뿔: 아주 쉽게 읽는 코드 설명

이 문서는 [1-14.cpp](../1-4/1-4/1-14.cpp)를 처음 읽는 사람을 위한 설명이다.

이 프로그램은 **점을 연결해 도형을 만들고, 키보드로 그 도형을 움직이는 프로그램**이다.

처음에는 아래 세 가지만 기억하면 된다.

1. **데이터:** 도형의 점과 색상을 저장한다.
2. **입력:** 키를 누르면 위치나 회전 방향을 바꾼다.
3. **그리기:** 바뀐 값으로 화면을 다시 그린다.

본문의 코드 조각은 원본의 일부다. 조각 하나만 복사해서 실행하는 것이 아니라 원본과 함께 읽는다. 뜻을 쉽게 보여 주기 위해 바꿔 쓴 코드는 **설명용 예시**라고 표시했다.

## 먼저 프로그램을 실행해 본다

다음 순서로 직접 눌러 보면 코드를 읽기 쉽다.

1. 처음에는 기울어진 육면체가 보인다.
2. `p`를 누르면 사각뿔이 된다.
3. 오른쪽 방향키를 누르면 도형만 오른쪽으로 간다.
4. `x`를 한 번 누르면 도형이 계속 회전한다.
5. `s`를 누르면 가운데로 돌아오고 회전이 멈춘다.
6. `w`를 누르면 면 없이 모서리만 보인다.
7. `h`를 누르면 뒤에 가려진 부분의 표시가 바뀐다.

| 키 | 하는 일 |
| --- | --- |
| `c` | 육면체 선택 |
| `p` | 사각뿔 선택 |
| `h` | 가려진 면·모서리 숨기기 켜기/끄기 |
| `w` | 모서리만 그리기: 와이어 |
| `Shift+w` | 면을 채워 그리기: 솔리드 |
| `x`, `Shift+x` | x 회전을 서로 반대 방향으로 시작 |
| `y`, `Shift+y` | y 회전을 서로 반대 방향으로 시작 |
| 방향키 | 도형 이동 |
| `s` | 위치·각도 초기화, 모든 회전 정지 |
| `Esc` | 종료 |

대문자 명령은 **Shift를 누른 채 입력한다.** 현재 코드는 Caps Lock으로 구분하지 않는다.

# 1부 프로그램의 큰 흐름부터 이해한다

## 1 가장 중요한 함수 세 개를 먼저 찾는다

함수는 **특정 일을 하는 코드에 이름을 붙인 것**이다. 먼저 다음 세 함수만 찾는다.

| 함수 | 쉬운 뜻 |
| --- | --- |
| `KeyCallback()` | 어떤 키를 눌렀는지 확인한다. |
| `UpdateAnimation()` | 회전 각도를 조금 바꾼다. |
| `DrawScene()` | 현재 상태대로 그림을 그린다. |

예를 들어 오른쪽 방향키를 누르면 다음 일이 일어난다.

```text
KeyCallback(): 오른쪽 위치값을 조금 늘린다.
DrawScene(): 그 위치값을 사용해 도형을 그린다.
결과: 도형이 오른쪽으로 움직인다.
```

입력 함수에서 직접 그림을 그리는 것이 아니다. **입력은 값을 바꾸고, 그리기 함수는 그 값을 읽는다.**

## 2 실행은 main에서 시작한다

파일 맨 아래의 `main()`이 프로그램의 출발점이다.

처음에는 창, 셰이더, 도형 데이터를 준비한다. 그다음 반복문을 계속 실행한다.

현재 반복문에서 중요한 호출만 추리면 다음과 같다.

```cpp
// 설명용 예시: 원본 반복문의 핵심 순서만 표시했다.
glfwPollEvents();
UpdateAnimation(deltaTime);
DrawScene(transformLocation);
glfwSwapBuffers(window);
```

| 코드 | 하는 일 |
| --- | --- |
| `glfwPollEvents()` | 키보드와 창 관련 이벤트를 처리한다. |
| `UpdateAnimation(deltaTime)` | 지난 시간만큼 회전 각도를 바꾼다. |
| `DrawScene(transformLocation)` | 도형과 좌표축을 그린다. |
| `glfwSwapBuffers(window)` | 완성한 그림을 보여 준다. |

이 과정을 한 번 진행해 화면을 만드는 것을 **프레임**이라고 한다.

```text
첫 번째 프레임: 30도인 도형을 그린다.
다음 프레임: 조금 더 회전한 도형을 그린다.
다음 프레임: 다시 조금 더 회전한 도형을 그린다.
```

이 그림들이 연속해서 보이면 움직이는 것처럼 보인다.

## 3 현재 상태를 변수에 저장한다

변수는 **프로그램이 기억하는 값**이다.

```cpp
int objectType = 0;
bool hiddenSurface = true;
bool wireframe = false;
float positionX = 0.0f;
float positionY = 0.0f;
float angleX = startAngleX;
float angleY = startAngleY;
int rotationX = 0;
int rotationY = 0;
```

한꺼번에 외우지 말고 역할별로 나눠 본다.

| 변수 | 프로그램이 기억하는 내용 |
| --- | --- |
| `objectType` | 육면체인지 사각뿔인지 |
| `hiddenSurface` | 가려진 부분을 숨길지 |
| `wireframe` | 면 대신 모서리만 그릴지 |
| `positionX`, `positionY` | 도형을 어디로 옮겼는지 |
| `angleX`, `angleY` | 도형이 얼마나 회전했는지 |
| `rotationX`, `rotationY` | 회전을 멈출지, 어느 방향으로 진행할지 |

자료형도 간단히 구분한다.

- `int`: 0, 1, -1 같은 정수.
- `float`: 0.1, 30.0 같은 소수도 저장하는 수.
- `bool`: `true` 또는 `false`. 켜짐/꺼짐을 표현하기 좋다.

**각도와 회전 방향은 다른 값이다.**

```text
angleX = 30: 현재 30도로 기울어져 있다.
rotationX = 0: 그 각도에서 멈춘다.
rotationX = 1: 각도를 계속 늘린다.
rotationX = -1: 각도를 계속 줄인다.
```

# 2부 도형을 만드는 방법을 이해한다

## 4 위치는 x, y, z 세 수로 적는다

종이에 점을 찍을 때는 가로와 세로 위치가 필요하다. 3차원에서는 깊이 위치가 하나 더 필요하다.

```text
x: 좌우 위치
 y: 상하 위치
 z: 앞뒤 위치
```

현재 프로그램에서는 x가 커지면 오른쪽, y가 커지면 위쪽이다. 투영 행렬 없이 깊이를 비교하므로 변환 후 z가 작은 쪽이 가까운 쪽이다.

```text
(0, 0, 0): 도형을 만드는 기준점
(0.4, 0, 0): 기준점에서 오른쪽으로 0.4
(0, 0.4, 0): 기준점에서 위쪽으로 0.4
```

0.4는 0.4픽셀이라는 뜻이 아니다. **도형을 정의할 때 사용하는 좌표 단위**다. 화면에서 몇 픽셀로 보일지는 화면 크기와 뷰포트 설정이 정한다.

## 5 점 하나에 위치와 색상을 묶는다

컴퓨터 그래픽스에서는 도형을 만드는 점을 **정점**이라고 부른다.

```cpp
struct Vertex
{
    float x, y, z;
    float red, green, blue;
};
```

`struct`는 관련 있는 값을 묶는 문법이다. `Vertex` 하나에는 다음 값이 들어간다.

```text
위치: x, y, z
색상: 빨강, 초록, 파랑
```

다음은 **설명용 예시**다.

```cpp
Vertex point = { -0.4f, -0.4f, 0.4f, 1.0f, 0.0f, 0.0f };
```

앞의 세 수가 위치이고, 뒤의 세 수가 색상이다.

```text
위치: (-0.4, -0.4, 0.4)
색상: (1, 0, 0), 즉 빨강
```

색상값은 여기서 0부터 1까지 사용한다.

| 색상값 | 색 |
| --- | --- |
| `(1, 0, 0)` | 빨강 |
| `(0, 1, 0)` | 초록 |
| `(0, 0, 1)` | 파랑 |
| `(1, 1, 0)` | 노랑 |
| `(1, 1, 1)` | 흰색 |

`0.4f` 뒤의 `f`는 `float` 값이라는 표시다.

## 6 육면체는 꼭짓점 8개로 만든다

`cubePoints[8]`에는 꼭짓점 8개가 들어 있다.

**배열은 같은 종류의 값을 여러 칸에 저장하는 것**이다. 번호는 0부터 시작한다. 따라서 `cubePoints[0]`이 첫 번째 점이고, `cubePoints[7]`이 마지막 점이다.

앞쪽 점 네 개를 그림으로 보면 다음과 같다.

```text
3 -------- 2
|          |
|   앞면   |
|          |
0 -------- 1
```

0~3번은 앞쪽 점이고, 4~7번은 뒤쪽 점이다.

위치는 각 방향으로 -0.4 또는 0.4를 사용한다. 한 변의 길이는 다음과 같다.

```text
0.4 - (-0.4) = 0.8
```

각 꼭짓점에는 서로 다른 색상이 들어 있다. 같은 꼭짓점을 여러 면에서 사용해도 그 점의 색상은 같다.

## 7 면은 삼각형으로 만든다

이 프로그램은 면을 삼각형으로 그린다. 삼각형 하나에는 점 세 개가 필요하다.

앞면 사각형은 삼각형 두 개로 나눌 수 있다.

```text
삼각형 하나: 0번, 1번, 2번 점
삼각형 하나 더: 0번, 2번, 3번 점
두 삼각형을 합치면 사각형 앞면
```

`cubeTriangles`에 들어 있는 `0, 1, 2, 0, 2, 3`이 이 뜻이다.

| 배열 | 저장하는 것 |
| --- | --- |
| `cubePoints` | 실제 점의 위치와 색상 |
| `cubeTriangles` | 삼각형으로 연결할 점의 번호 |

예를 들어 `cubeTriangles`에서 2를 읽으면 `cubePoints[2]`를 사용한다.

육면체의 전체 면을 그릴 때는 정점을 36개 나열한다.

```text
면 6개 × 면마다 삼각형 2개 × 삼각형마다 점 3개 = 36개
```

**실제 꼭짓점은 8개다.** 면마다 같은 꼭짓점을 반복해서 나열하기 때문에 그릴 때 사용하는 목록은 36개가 된다.

사각뿔은 바닥 점 4개와 꼭대기 점 1개를 사용한다. 옆면 삼각형 4개와 바닥 삼각형 2개를 그리므로 정점 목록은 18개다.

```text
(옆면 4개 + 바닥 2개) × 3 = 18개
```

## 8 와이어는 점 두 개를 연결한 선으로 만든다

**솔리드**는 면을 채운 도형이다. **와이어**는 모서리만 보이는 도형이다.

선 하나는 점 두 개를 연결한다.

```text
0, 1: 0번 점과 1번 점을 연결
1, 2: 1번 점과 2번 점을 연결
```

`cubeEdges`와 `pyramidEdges`에는 이렇게 연결할 점 번호가 들어 있다.

| 도형 | 모서리 수 | 선을 그릴 때 나열할 정점 수 |
| --- | --- | --- |
| 육면체 | 12개 | 12 × 2 = 24개 |
| 사각뿔 | 8개 | 8 × 2 = 16개 |

삼각형으로 나눈 면의 내부 대각선은 실제 육면체 모서리가 아니다. 그래서 **면 목록과 모서리 목록을 따로 준비한다.**

## 9 CreateVertices는 그릴 점을 차례대로 복사한다

`CreateVertices()`는 GPU에 보낼 점 목록을 만든다. GPU는 그림을 그리는 작업을 처리하는 장치다.

```cpp
int count = 0;
for (int i = 0; i < cubeFaceCount; i++)
    vertices[count++] = cubePoints[cubeTriangles[i]];
```

이 줄이 어려우면 아래 **설명용 예시**로 나눠 읽는다.

```cpp
int pointNumber = cubeTriangles[i];
vertices[count] = cubePoints[pointNumber];
count = count + 1;
```

1. 이번에 사용할 점 번호를 찾는다.
2. 그 점의 위치와 색상을 새 목록에 넣는다.
3. 다음 칸으로 이동한다.

`count++`는 현재 번호를 사용한 뒤 1을 더한다는 뜻이다.

`vertices[100]`에는 다음 순서로 넣는다.

| 넣는 데이터 | 시작 번호 | 개수 |
| --- | --- | --- |
| 육면체 면 | 0 | 36 |
| 사각뿔 면 | 36 | 18 |
| 육면체 모서리 | 54 | 24 |
| 사각뿔 모서리 | 78 | 16 |
| 좌표축 | 94 | 6 |

합계는 100개다. 이 목록은 시작할 때 한 번 만든다. 회전할 때마다 다시 만드는 것이 아니다.

# 3부 키를 누르면 어떻게 움직이는지 이해한다

## 10 방향키는 위치값만 바꾼다

오른쪽 방향키의 실제 코드는 다음과 같다.

```cpp
positionX += moveStep;
```

`+=`는 더해서 저장하라는 뜻이다. 기본 `moveStep`은 0.1이다.

```text
시작 위치: 0.0
오른쪽 한 번: 0.1
오른쪽 한 번 더: 0.2
```

왼쪽은 빼고, 위쪽은 `positionY`에 더하고, 아래쪽은 `positionY`에서 뺀다.

**점을 전부 하나씩 고치는 것이 아니라 “얼마나 옮길지”를 변수에 저장한다.** 그리기 함수가 이동을 적용한다.

방향키를 누르고 있으면 반복 입력도 처리한다. 현재 코드는 이동 범위를 막지 않으므로 계속 이동하면 화면 밖으로 나갈 수 있다.

## 11 x 키는 회전 방향을 저장한다

```cpp
else if (key == GLFW_KEY_X)
{
    rotationY = 0;
    rotationX = 1;
    if (shiftPressed)
        rotationX = -1;
}
```

이 코드를 말로 읽으면 다음과 같다.

```text
x를 누르면 y축 회전을 멈추고 x축 각도를 늘리는 방향으로 설정한다.
Shift도 누르고 있으면 각도를 줄이는 방향으로 설정한다.
```

키를 뗀 뒤에도 저장한 방향은 유지된다. 그래서 한 번만 눌러도 계속 돈다. `y`도 같은 방식이다.

`x` 다음에 `y`를 누르면 x축 회전은 멈추고 y축만 회전한다. `y` 다음에 `x`를 누르면 반대로 동작한다. 이전 축의 각도는 현재 자세로 유지하고 회전 애니메이션만 멈춘다. Shift를 함께 눌러도 같은 축 전환 규칙을 사용한다. 같은 키를 다시 눌러도 정지하지 않는다. `s`는 모든 회전을 멈추고 위치와 각도를 초기화한다.

## 12 회전량은 속도와 지난 시간을 곱해 구한다

```cpp
angleX += rotationX * rotationSpeed * deltaTime;
```

먼저 두 용어를 알아 둔다.

- `rotationSpeed`: 1초에 몇 도 돌지. 기본값은 60도/초다.
- `deltaTime`: 직전 프레임 이후 지난 시간. 단위는 초다.

예를 들어 0.1초가 지났다면 다음과 같다.

```text
회전 방향: 1
회전 속도: 60도/초
지난 시간: 0.1초
회전량: 1 × 60 × 0.1 = 6도

현재 각도가 30도라면 다음 각도는 36도
```

방향이 -1이면 6도를 빼고, 방향이 0이면 그대로 둔다.

왜 시간을 곱할까? **빠른 컴퓨터와 느린 컴퓨터가 같은 시간 동안 비슷한 각도를 돌게 하려는 것**이다. 프레임마다 무조건 1도를 더하면 프레임이 많은 컴퓨터에서 더 빨리 돈다.

원본은 `glfwGetTime()`으로 시간을 읽고, 이전 시간과의 차이를 구한다. 오래 멈춘 뒤 갑자기 크게 돌지 않게 한 번의 시간 차이는 최대 0.1초로 제한한다. 제한이 걸리면 실제로 지난 시간 전체를 따라잡지는 않는다.

한 바퀴를 넘으면 360도를 빼거나 더한다. 예를 들어 365도는 5도, -5도는 355도와 같은 방향이다.

## 13 s는 값을 처음 상태로 돌린다

```cpp
void ResetObject()
{
    positionX = 0.0f;
    positionY = 0.0f;
    angleX = startAngleX;
    angleY = startAngleY;
    rotationX = 0;
    rotationY = 0;
}
```

뜻은 다음 세 줄이다.

1. 위치를 가운데로 돌린다.
2. 각도를 시작 각도인 x축 30도, y축 30도로 돌린다.
3. 두 회전 방향을 0으로 만들어 멈춘다.

선택한 도형과 와이어/솔리드, 은면 제거 설정은 유지된다. 예를 들어 사각뿔을 선택한 뒤 `s`를 눌러도 육면체로 바뀌지는 않는다.

# 4부 컴퓨터가 화면에 그리는 방법을 이해한다

## 14 행렬은 이동·회전 계산을 묶은 것이다

**행렬**은 수를 표처럼 모아 놓은 것이다. 이 코드에서는 점을 옮기거나 돌리는 계산을 담는다.

처음에는 표 안의 모든 수를 계산할 필요가 없다. 다음 함수의 역할부터 이해한다.

| 코드 | 쉬운 뜻 |
| --- | --- |
| `glm::mat4(1.0f)` | 아무것도 바꾸지 않는 상태에서 시작 |
| `glm::translate(...)` | 이동 계산 추가 |
| `glm::rotate(...)` | 회전 계산 추가 |
| `glm::radians(...)` | 도 단위를 회전 함수가 사용하는 라디안 단위로 변환 |

현재 도형의 행렬은 다음 코드로 만든다.

```cpp
glm::mat4 model = glm::mat4(1.0f);
model = glm::translate(model, glm::vec3(positionX, positionY, 0.0f));
model = glm::rotate(model, glm::radians(angleY), glm::vec3(0.0f, 1.0f, 0.0f));
model = glm::rotate(model, glm::radians(angleX), glm::vec3(1.0f, 0.0f, 0.0f));
```

여기서 `glm::vec3(...)`는 수 세 개를 묶는 표현이다.

- `(positionX, positionY, 0)`은 이동량이다.
- `(1, 0, 0)`은 x 회전축 방향이다.
- `(0, 1, 0)`은 y 회전축 방향이다.

**이 코드에서는 뒤에 적은 회전부터 점에 적용된다.** 실제 적용 순서는 다음과 같다.

```text
x축으로 회전한다.
y축으로 회전한다.
마지막에 원하는 위치로 옮긴다.
```

그래서 도형을 오른쪽으로 이동한 뒤 회전해도 화면 중앙 주위를 크게 돌지 않는다. 회전한 도형을 이동 위치에 놓는 것이다.

회전 기준은 도형을 만들 때의 원점 `(0, 0, 0)`이다. 육면체에서는 중심이다. 사각뿔의 무게중심을 따로 계산하는 것은 아니다.

두 회전은 합쳐서 적용되므로 서로 영향을 준다. x 회전과 y 회전 순서를 바꾸면 보통 다른 자세가 된다.

## 15 이동과 회전 행렬만 셰이더에 보낸다

현재 코드는 별도의 투영 행렬을 사용하지 않는다. 이동·회전을 계산한 `model`을 그대로 전달한다.

```cpp
glUniformMatrix4fv(transformLocation, 1, GL_FALSE, glm::value_ptr(model));
```

변환한 좌표의 w는 1이다. 화면에 보이는 NDC 범위는 x, y, z 각각 `-1 ~ 1`이다. 도형을 이동해 이 범위를 벗어나면 일부가 잘릴 수 있다.

좌표축에는 `glm::mat4(1.0f)`로 만든 단위 행렬을 전달한다. 따라서 도형을 이동하거나 회전해도 좌표축은 고정된다.

## 16 셰이더는 GPU에서 실행하는 작은 프로그램이다

공부할 셰이더 파일은 두 개다.

| 파일 | 하는 일 |
| --- | --- |
| [1-14-vertex.glsl](../1-4/1-4/1-14-vertex.glsl) | 점이 어디에 나타날지 계산 |
| [1-14-fragment.glsl](../1-4/1-4/1-14-fragment.glsl) | 화면에 쓸 색상 출력 |

정점 셰이더의 핵심은 다음 한 줄이다.

```glsl
gl_Position = transform * vec4(position, 1.0);
```

| 부분 | 뜻 |
| --- | --- |
| `position` | 원래 점의 위치 |
| `transform` | C++에서 만든 이동·회전 계산 |
| `gl_Position` | 계산한 위치를 다음 그리기 단계에 전달하는 값 |

`vec4(position, 1.0)`은 위치 세 수에 1을 하나 붙이는 표현이다. 4 × 4 행렬로 점의 이동까지 계산하기 위한 형태다. 이를 **동차 좌표**라고 부른다. 처음에는 마지막 1을 유지하면 된다.

`gl_Position`은 최종 픽셀 번호 자체가 아니다. 이후 그리기 과정에서 화면 위치로 바뀐다.

C++는 다음 코드로 행렬을 셰이더에 보낸다.

```cpp
glUniformMatrix4fv(transformLocation, 1, GL_FALSE, glm::value_ptr(model));
```

처음에는 “`model` 행렬을 셰이더의 `transform`에 보낸다”라고 읽는다. `transformLocation`은 받을 자리이고, `glm::value_ptr()`는 행렬 데이터의 주소를 얻는다. `GL_FALSE`는 행과 열을 뒤집지 않는다는 뜻이다.

셰이더의 `uniform`은 이런 식으로 **C++가 설정해 주는 값**이다.

## 17 꼭짓점 사이의 색상은 중간 색으로 이어진다

정점 셰이더는 각 점의 색상을 다음 단계로 넘긴다.

```glsl
vertexColor = color;
```

점마다 빨강, 초록, 파랑 등 다른 색상을 넣었으므로 삼각형 안에는 중간 색이 나타난다.

```text
한쪽 꼭짓점: 빨강
다른 꼭짓점: 파랑
사이 부분: 빨강과 파랑이 섞인 색
```

이렇게 사이의 값을 계산하는 것을 **보간**이라고 한다.

조각 셰이더는 받은 색상을 출력한다.

```glsl
finalColor = vec4(vertexColor, 1.0);
```

마지막 1은 알파값이다. 현재 코드는 투명도 혼합을 사용하지 않는다.

밝고 어두운 색이 보여도 조명을 계산한 것은 아니다. 이 프로그램의 색상 변화는 꼭짓점에 넣은 색상에서 나온다.

## 18 은면 제거는 앞의 면이 뒤의 면을 가리게 한다

상자를 보면 앞면 뒤에 있는 면은 보이지 않는다. 컴퓨터도 이렇게 판단해야 한다.

현재 코드는 **깊이 검사**를 사용한다. 화면의 같은 위치에 여러 면이 겹칠 때 어느 부분이 더 가까운지 비교한다.

```cpp
glEnable(GL_DEPTH_TEST);
```

깊이 검사를 켜는 명령이다. 끄는 명령은 다음과 같다.

```cpp
glDisable(GL_DEPTH_TEST);
```

`h`를 누르면 사용할지 말지 바뀐다.

```cpp
hiddenSurface = !hiddenSurface;
```

`!`는 참과 거짓을 반대로 만든다. 켜져 있으면 끄고, 꺼져 있으면 켠다.

| 저장 공간 | 기억하는 것 |
| --- | --- |
| 색상 버퍼 | 화면에 쓸 색상 |
| 깊이 버퍼 | 같은 화면 위치에서의 앞뒤 깊이 |

현재 설정에서는 **작은 깊이 값이 가까운 쪽**이다. `GL_LESS`는 새 깊이가 저장된 깊이보다 작을 때 통과시킨다. 깊이 값은 원래 꼭짓점의 z를 그대로 저장한 값이 아니라 이동·회전과 NDC의 깊이 범위 변환을 거친 값이다.

매 프레임 두 버퍼를 함께 지운다.

```cpp
glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT);
```

말로 읽으면 “이전 색상과 이전 깊이를 지우고 새 그림을 시작한다”다.

깊이 검사를 끄면 가까운지 비교하지 않으므로 그리는 순서가 겹침에 영향을 준다. 도형이 자동으로 반투명해지는 것은 아니다.

### 와이어도 기본 깊이 검사만 사용한다

PDF 「지엘3 좌표계 변환 1」 29~30쪽처럼 깊이 버퍼를 지우고 `GL_DEPTH_TEST`를 켜거나 끈다.

솔리드는 삼각형 면을 그리므로 앞면이 뒤쪽 면을 가린다. 와이어는 모서리 선만 그리므로 선끼리 겹친 위치의 깊이만 비교한다. 선 사이의 빈 영역이 뒤쪽 모서리를 면처럼 가리지는 않는다.

색상 쓰기를 끈 채 면을 먼저 그리는 처리나 깊이 보정은 사용하지 않는다.

## 19 좌표축은 도형과 따로 그린다

도형에는 이동·회전을 적용한다. 좌표축에는 **단위 행렬을 적용한다.**

```text
도형: 회전하고 이동한 뒤 화면에 표시
좌표축: 원래 위치 그대로 화면에 표시
```

그래서 방향키나 회전 키를 눌러도 좌표축이 따라 움직이지 않는다.

| 색 | 안내하는 방향 |
| --- | --- |
| 빨강 | x축 표시: 오른쪽 위로 완만한 대각선 |
| 초록 | y축 표시: 수직 |
| 파랑 | z축 표시: 오른쪽 아래로 대각선 |

**파란 대각선은 화면 안내용 그림이다.** 실제 z축은 화면 안팎으로 향해 점처럼 보이므로 대각선 표시를 따로 만들었다.

좌표축에도 `h`로 설정한 깊이 검사를 적용한다. 켜져 있으면 더 가까운 면에 가려질 수 있고, 꺼져 있으면 마지막에 그린 축이 도형 위에 보인다. 축의 위치와 방향은 그대로 고정된다.

# 5부 조금 더 자세히 읽고 싶을 때

앞의 내용을 먼저 이해한 뒤 읽는다. 아래 내용은 프로그램을 준비하고 정확히 그리기 위한 세부 설정이다.

## 20 VBO와 VAO는 데이터와 읽는 방법을 준비한다

| 이름 | 처음에는 이렇게 이해한다 |
| --- | --- |
| VBO | OpenGL에서 사용할 정점 데이터를 보관하는 버퍼 |
| VAO | 그 데이터를 읽는 방법을 기억하는 설정 객체 |

정점 하나는 다음 순서로 저장된다.

```text
x, y, z, 빨강, 초록, 파랑
```

`glVertexAttribPointer()`로 위치와 색상을 구분해서 읽도록 설정한다.

- 입력 0은 앞의 위치 세 값을 읽는다.
- 입력 1은 위치 세 값을 건너뛰고 색상 세 값을 읽는다.
- `sizeof(Vertex)`는 다음 점까지 건너갈 간격이다.

이 입력 번호는 셰이더와 맞아야 한다.

```glsl
layout (location = 0) in vec3 position;
layout (location = 1) in vec3 color;
```

`location = 0`이 위치를 받고, `location = 1`이 색상을 받는다. `vec3`는 수 세 개를 묶는 자료형이다.

## 21 glDrawArrays는 목록에서 사용할 부분을 고른다

육면체 솔리드를 그리는 명령을 숫자로 풀면 다음과 같다. **설명용 예시**다.

```cpp
glDrawArrays(GL_TRIANGLES, 0, 36);
```

| 값 | 뜻 |
| --- | --- |
| `GL_TRIANGLES` | 점 세 개씩 묶어 삼각형으로 그리기 |
| `0` | 목록의 0번 점부터 시작 |
| `36` | 정점 36개 사용 |

**36은 삼각형 개수도, 끝 번호도 아니다.** 사용할 정점 개수다. 실제로는 삼각형 12개가 된다.

모서리에는 `GL_LINES`를 사용한다. 이 경우 점 두 개씩 묶어 선을 만든다.

`objectType`이 0이면 육면체 범위를 사용하고, 1이면 사각뿔 범위를 사용한다. `wireframe`에 따라 면 목록이나 모서리 목록을 고른다.

## 22 Shift와 키 반복은 따로 확인한다

`KeyCallback()`의 `key`는 어떤 키인지 알려 준다. `mods`에는 Shift 같은 보조키 상태가 들어 있다.

```cpp
bool shiftPressed = (mods & GLFW_MOD_SHIFT) != 0;
```

처음에는 “Shift가 눌렸는지 확인한다”라고 읽는다. 여기의 `&`는 보조키 상태에서 Shift 정보를 골라내는 연산이다.

```cpp
wireframe = !shiftPressed;
```

Shift가 없으면 와이어, Shift가 있으면 솔리드다. `w`는 설정을 뒤집는 토글이 아니라 와이어를 선택하는 명령이다.

`action`은 키를 처음 눌렀는지, 누른 채 반복되는지, 뗐는지를 알려 준다.

- 방향키는 처음 누름과 반복 입력을 처리한다.
- 도형 선택, `h`, 회전 명령 등은 처음 누를 때만 처리한다.

그래야 `h`를 길게 누르는 동안 설정이 계속 뒤집히지 않는다.

## 23 PDF의 은면 제거 코드를 읽는다

`DrawScene()`에서 매 프레임 색상 버퍼와 깊이 버퍼를 함께 지운다. `h`는 `hiddenSurface`를 바꾸고, 그 값으로 깊이 검사를 켜거나 끈다.

```cpp
glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT);

if (hiddenSurface)
    glEnable(GL_DEPTH_TEST);
else
    glDisable(GL_DEPTH_TEST);
```

이 설정은 도형과 좌표축에 모두 적용된다. 깊이 비교는 OpenGL 기본값인 `GL_LESS`를 사용한다. 별도의 깊이 보정이나 면 컬링은 추가하지 않는다.

## 24 창이 직사각형이어도 도형을 늘리지 않는다

뷰포트는 **그림을 표시할 화면 영역**이다.

현재 `FramebufferSizeCallback()`은 너비와 높이 중 작은 값을 골라 정사각형 영역을 만든다.

```text
실제 그리기 영역이 800 × 600일 때:
정사각형 뷰포트는 600 × 600
왼쪽 여백은 100픽셀
오른쪽 여백도 100픽셀
```

그래서 창이 직사각형이어도 도형이 가로로 늘어나지 않는다. 화면 배율에 따라 실제 픽셀 수는 창 크기와 다를 수 있다. 코드는 실제 그리기 영역 크기를 확인해 설정한다.

위 예에서는 좌표 범위 2단위(-1 ~ 1)를 600픽셀로 표시한다.

```text
좌표 1단위는 300픽셀
좌표 0.1단위는 30픽셀
```

따라서 기본 방향키 이동량 0.1은 이 조건에서 약 30픽셀이다.

## 25 시작할 때 준비하는 함수도 알아 둔다

| 함수 | 쉬운 역할 |
| --- | --- |
| `glfwInit()` | 창 관련 기능 준비 |
| `glfwCreateWindow()` | 창 생성 |
| `glfwMakeContextCurrent()` | 그림을 그릴 창의 OpenGL 환경 선택 |
| `glewInit()` | OpenGL 함수를 사용할 준비 |
| `ReadShaderFile()` | 셰이더 파일의 글자를 읽기 |
| `CompileShader()` | 셰이더 코드를 사용할 수 있도록 컴파일 |
| `glLinkProgram()` | 정점·조각 셰이더를 연결 |
| `CreateVertices()` | 정점 목록 만들기 |

GLFW는 창과 입력을 다루는 도구다. GLEW는 OpenGL 함수 접근을 준비하고, GLM은 행렬 계산을 도와준다.

셰이더 파일을 읽을 때는 작업 폴더에서 먼저 찾고, 없으면 소스 파일 옆에서 찾는다. 프로젝트 설정은 실행 파일 폴더에도 셰이더를 복사한다.

C++ 빌드와 셰이더 컴파일은 서로 다르다. C++ 빌드가 성공해도 셰이더 파일에 오류가 있으면 실행할 때 실패할 수 있다. 현재 코드는 각각 성공 여부를 검사한다.

| 바꿀 값 | 연습값 | 예상 결과 |
| --- | --- | --- |
| `startAngleX`, `startAngleY` | 둘 다 `0.0f` | 기울지 않은 상태로 시작 |
| `rotationSpeed` | `30.0f` | 기본보다 절반 속도로 회전 |
| `moveStep` | `0.05f` | 방향키 한 번의 이동량이 절반 |

시작 각도를 바꿀 때는 `startAngleX`, `startAngleY`를 바꾼다. `s`로 돌아갈 각도도 이 두 값을 사용한다.

점의 색상을 바꾸고 싶다면 `cubePoints`에서 **뒤의 색상 세 값만** 바꾼다.

```text
위치 값 세 개: 그대로 둔다.
색상 값 세 개: (1, 0, 0)을 (1, 1, 1)로 바꾼다.
결과: 빨간 꼭짓점이 흰색 꼭짓점이 된다.
```

크기를 바꾸고 싶다면 **앞의 위치 세 값**에서 -0.4와 0.4를 -0.3과 0.3으로 바꾼다. 한 변은 0.8에서 0.6으로 줄어든다. 부호는 유지하고 색상 부분은 건드리지 않는다.

## 27 이 여섯 질문에 답해 본다

1. 오른쪽 방향키를 누르면 어떤 값이 바뀔까?
2. `angleX`와 `rotationX`는 어떻게 다를까?
3. 육면체 꼭짓점은 8개인데 면을 그릴 목록은 왜 36개일까?
4. 도형이 회전해도 좌표축이 움직이지 않는 이유는 무엇일까?
5. 와이어에서 깊이 검사를 켜도 뒤쪽 모서리 전체가 가려지지 않는 이유는 무엇일까?
6. `s`를 눌렀을 때 사각뿔이 육면체로 바뀔까?

### 답

1. `positionX`에 `moveStep`을 더한다.
2. 현재 각도와 앞으로 돌 방향이다.
3. 면마다 삼각형을 만들면서 같은 점을 반복해서 사용하기 때문이다.
4. 좌표축에는 도형의 이동·회전을 적용하지 않기 때문이다.
5. 선만 그리므로 선 사이의 빈 영역에는 가림에 사용할 면 깊이가 없기 때문이다.
6. 바뀌지 않는다. 선택한 도형은 유지한다.

## 28 마지막으로 실행 동작을 확인한다

- `c`, `p`로 두 도형을 선택한다.
- 방향키로 이동하고 좌표축이 고정되는지 본다.
- 이동한 뒤 회전을 시작해 이동 위치에서 도는지 본다.
- `x`, `Shift+x`, `y`, `Shift+y`의 방향 차이를 확인한다.
- `w`, `Shift+w`로 모서리와 면 표시를 바꾼다.
- `h`로 가려진 부분의 표시 차이를 본다.
- `s`로 중앙·시작 각도에 돌아오고 두 회전이 멈추는지 본다.

이 프로젝트의 실행 파일 이름은 `1-4.exe`이고, 과제 코드는 `1-14.cpp`다. 여러 과제의 `main()`을 함께 빌드하면 중복 정의 오류가 날 수 있다.

# 7부 변경 사항: 회전 축 전환 (2026-10-12)

## 29 새 축을 선택하면 이전 축의 회전을 멈춘다

### 무엇을 바꿨는가

이전에는 `x`를 누른 뒤 `y`를 누르면 x축 회전과 y축 회전이 동시에 진행됐다. 두 회전 방향을 따로 저장하면서 이전 축의 값을 지우지 않았기 때문이다.

수정 후에는 **마지막으로 선택한 축 하나만 회전한다.**

| 입력 순서 | 수정 전 | 수정 후 |
| --- | --- | --- |
| `x` 다음 `y` | 두 축 모두 양의 방향으로 회전 | x축 정지, y축만 양의 방향으로 회전 |
| `y` 다음 `x` | 두 축 모두 양의 방향으로 회전 | y축 정지, x축만 양의 방향으로 회전 |
| `x` 다음 `Shift+y` | x축은 양의 방향, y축은 음의 방향으로 회전 | x축 정지, y축만 음의 방향으로 회전 |
| `y` 다음 `Shift+x` | y축은 양의 방향, x축은 음의 방향으로 회전 | y축 정지, x축만 음의 방향으로 회전 |

### 수정한 코드

수정 위치는 [1-14.cpp의 KeyCallback()](../1-4/1-4/1-14.cpp)이다.

```cpp
else if (key == GLFW_KEY_X)
{
    rotationY = 0;
    rotationX = 1;
    if (shiftPressed)
        rotationX = -1;
}
else if (key == GLFW_KEY_Y)
{
    rotationX = 0;
    rotationY = 1;
    if (shiftPressed)
        rotationY = -1;
}
```

추가한 코드는 두 줄이다.

- `rotationY = 0;`: x축 회전을 시작하기 전에 y축 회전을 멈춘다.
- `rotationX = 0;`: y축 회전을 시작하기 전에 x축 회전을 멈춘다.

`UpdateAnimation()`은 회전 방향에 속도와 지난 시간을 곱해 각도를 바꾼다. 회전 방향이 0이면 더하는 값도 0이므로 그 축의 각도는 더 이상 변하지 않는다.

### 회전을 멈추는 것과 각도를 초기화하는 것은 다르다

이 변경은 **회전 애니메이션만 멈춘다.** `angleX`, `angleY`를 시작 각도로 돌리지는 않는다. 따라서 축을 바꿔도 도형은 현재 자세에서 새 축 회전을 시작한다. 이동 위치와 선택한 도형도 유지한다.

위치와 각도를 처음 상태로 돌리고 모든 회전을 멈추려면 기존의 `s` 명령을 사용한다.

### 확인한 결과

- 양의 방향과 음의 방향 모두 x축에서 y축으로 바꾸면 x축 각도가 더 이상 변하지 않는다.
- 양의 방향과 음의 방향 모두 y축에서 x축으로 바꾸면 y축 각도가 더 이상 변하지 않는다.
- [1-14 검사 프로그램](../1-4/1-4/tests/1-14-check.cpp)에 두 방향의 축 전환 검사를 추가했고, 기존 OpenGL 렌더링 검사도 통과했다.
- Debug x64 빌드를 확인했다.
