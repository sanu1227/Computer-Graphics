# AI 협업 개발 규칙

이 파일은 실제 게임 저장소 루트의 AGENTS.md로 사용할 템플릿이다. 기존 AGENTS.md가 있으면 기존 지침을 보존하며 합친다. 아래 TEAM.md와 작업 기록 경로는 팀이 사용하는 경로에 맞춘다.

## 작업 전

1. 적용되는 프로젝트 지침과 docs/TEAM.md를 읽는다.
2. TEAM.md에 지정된 공식 기획서의 관련 부분을 읽는다.
3. 자신의 작업 기록과 수정 범위가 겹치는 진행 중 작업의 기록을 확인한다.
4. 실제 코드, 현재 브랜치, Git 수정·삭제 상태를 확인한다.
5. 목표·수정 범위·완료 기준을 짧게 정리한다. 이미 배정된 범위의 구현과 검증은 진행한다.

새 작업·브랜치 변경·인계 시 다시 확인한다. 진행 중에는 바뀌었거나 불확실한 부분만 다시 읽는다. 문서가 없으면 존재한다고 가정하거나 삭제된 문서를 복원하지 않는다. 필요한 맥락을 확인하면서 독립적인 작업을 진행한다.

## 담당 범위

- 작업마다 ID, 담당자, 브랜치, 수정 파일·폴더, 완료 기준을 기록한다.
- 한 파일을 두 AI가 동시에 수정하지 않는다. 담당이 겹치면 해당 부분의 순서를 조율한다.
- MD는 잠금 장치가 아니다. 다른 PC의 진행 상황이 자동 반영된다고 가정하지 않는다.
- 합의된 담당 범위 안에서는 자율적으로 구현·검증한다. 범위 밖 변경이 필요하면 이유와 영향을 먼저 설명한다.
- 상대 담당 코드와 기존 변경을 임의로 덮어쓰거나 되돌리지 않는다.

## 공통 규칙과 기획

- 공통 함수의 이름·인자, 좌표계, 파일 형식, 자원 경로, 시작 코드, 빌드 설정은 영향받는 담당과 조율하고 변경한다.
- 이미 합의된 인터페이스 내부의 수정은 담당자가 진행한다.
- 다른 담당의 기능을 중복 구현하지 않는다. 필요한 인터페이스와 동작을 작업 기록에 남긴다.
- 게임 규칙·조작·개발 범위를 임의로 변경하지 않는다. 요청하지 않은 기능과 전면 정리를 함께 수행하지 않는다.
- 기획과 코드가 다르면 의도와 현재 구현의 차이를 확인한다. 제안과 채택된 결정을 구분한다.

## Git과 검증

- 기존 수정과 삭제를 보존한다. 충돌은 양쪽 의도를 확인해 해결한다.
- 강제 푸시·강제 초기화·일괄 삭제·임의 stash로 충돌을 덮지 않는다.
- 기능별 작업 브랜치와 분리된 작업 폴더를 사용한다. main 통합은 지정된 담당자가 수행한다.
- 커밋·푸시·병합은 사용자에게 허용받은 범위에서 수행한다. 이미 허용된 작업은 재승인을 요구하지 않는다.
- 커밋 전에 포함 파일을 확인하고 해당 작업만 포함한다.
- 변경에 맞는 검증을 한다. 빌드·실행·화면·실제 조작 확인을 구분하고 미검증 사항을 명시한다.

## 작업 후

- 자신의 docs/tasks/작업ID.md를 갱신한다.
- 변경 요약, 수정 파일, 검증 결과, 미검증 사항, 다른 담당에게 미치는 영향, 다음 작업을 남긴다.
- 커밋·푸시·통합 여부를 따로 기록한다. 수행하지 않은 작업을 완료로 표시하지 않는다.
- 중요한 AI 활용 사례의 요청 요약, 사람의 검토·수정, 확인 결과를 짧게 기록한다.
- 상대의 작업 기록은 임의로 변경하지 않는다. TEAM.md의 담당·공통 약속은 통합 담당자가 합의 내용을 반영한다.
