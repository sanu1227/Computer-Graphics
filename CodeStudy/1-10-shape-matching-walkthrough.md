# 1-10 도형 맞추기: 초보자를 위한 개발 순서와 코드 해설

이 문서는 [1-10.cpp](../1-4/1-4/1-10.cpp)를 처음부터 직접 작성한다고 가정하고 설명한다. 도형을 그리는 방법뿐 아니라 데이터를 어떤 순서로 설계하고, 마우스 입력과 완성 판정을 어떻게 연결하는지 다룬다. 과제 그림의 모양판 3개와 추가 모양판 2개를 기준으로 한다.

**먼저 구분할 것:** 파일에서 함수가 적힌 순서, 개발자가 기능을 만드는 순서, 프로그램이 실행되는 순서는 서로 다르다. 현재 파일은 C++ 함수들을 먼저 정의하고 `main()`을 맨 아래에 두었다. 이 문서는 기능을 하나씩 만들고 확인하기 좋은 **개발 순서**로 진행한다. 함수의 정의보다 먼저 호출하는 형태로 파일을 작성하고 싶다면 함수 선언을 앞에 추가해야 한다.

## 1. 빈 창을 먼저 띄운다

처음에는 도형·모양판·마우스 처리를 넣지 않는다. [`main()`](../1-4/1-4/1-10.cpp#L891)에서 다음 흐름만 완성한다.

헤더는 `#include <GL/glew.h>`를 `#include <GL/glfw3.h>`보다 앞에 둔다.

1. `glfwInit()`으로 GLFW를 초기화한다. 실패하면 오류를 출력하고 종료한다.
2. `glfwWindowHint()`로 OpenGL 3.3 Core Profile과 고정 크기 창을 설정한다.
3. `glfwCreateWindow()`로 창을 만들고 실패 여부를 확인한다.
4. `glfwMakeContextCurrent(window)`로 해당 창의 OpenGL 컨텍스트를 활성화한다.
5. **컨텍스트가 활성화된 뒤** `glewInit()`을 호출한다.
6. 반복문에서 화면을 지우고, 그린 화면을 보여주고, 입력 이벤트를 처리한다.
7. 종료 시 OpenGL 객체와 GLFW 창을 정리한다.

반복문의 기본형은 다음과 같다.

```cpp
while (!glfwWindowShouldClose(window))
{
    glClear(GL_COLOR_BUFFER_BIT);
    DrawScene();
    glfwSwapBuffers(window);
    glfwPollEvents();
}
```

`glClear()`는 이전 화면 내용을 지운다. `DrawScene()`은 이번 화면을 구성한다. `glfwSwapBuffers()`가 완성된 화면을 보여준다. `glfwPollEvents()`는 마우스와 키보드 이벤트를 받아 등록된 콜백 함수를 호출한다. 이벤트 처리 결과는 보통 다음 반복에서 화면에 나타난다.

첫 단계에서 `DrawScene()`은 비어 있는 함수로 만들거나 호출을 잠시 생략한다. 아직 함수가 없는데 호출만 적으면 C++ 컴파일 오류가 난다.

**확인:** 빈 창이 열리고 정상 종료되는지 확인한다. 아직 도형이 보이지 않는 것은 정상이다.

이 프로젝트에는 연습 번호마다 `main()`이 있다. [1-4.vcxproj](../1-4/1-4/1-4.vcxproj)에서 10번 소스만 빌드하고 9번을 제외해야 `main()` 중복 오류가 나지 않는다. 빌드 결과 파일명은 프로젝트 이름에 따라 `1-4.exe`일 수 있다.

## 2. 화면에서 사용할 수치를 정한다

[파일 앞부분의 상수](../1-4/1-4/1-10.cpp#L17)는 모든 위치 계산의 기준이다.

```cpp
constexpr int WINDOW_WIDTH = 1080;
constexpr int WINDOW_HEIGHT = 720;
constexpr int LEFT_AREA_WIDTH = 440;

constexpr float PIECE_SIZE = 40.0f;
constexpr float RIGHT_TRIANGLE_HEIGHT = 80.0f;
constexpr float SNAP_DISTANCE = 28.0f;
```

`constexpr`는 실행 중 바뀌지 않는 값이다. `x=0`부터 대략 `x=440`까지 왼쪽 조각 영역으로, 그 오른쪽을 모양판 영역으로 사용한다. 사각형 한 변과 정삼각형 한 변은 40픽셀이다. 직각삼각형은 너비 40픽셀, 높이 80픽셀의 사각형 절반을 차지한다. 목표 위치에서 28픽셀 이내에 조각을 놓으면 자동으로 붙을 수 있다.

화면에서 마우스와 도형의 좌표는 왼쪽 위를 `(0, 0)`으로 생각한다. 오른쪽으로 갈수록 `x`, 아래로 갈수록 `y`가 커진다. OpenGL 셰이더가 이 좌표를 화면 표시용 좌표로 바꾼다.

현재 창은 사용자가 크기를 바꿀 수 없게 설정했다. 창 좌표는 `1080 × 720`을 기준으로 쓰지만, 고해상도 화면의 실제 프레임버퍼 크기는 다를 수 있다. 그래서 `glViewport()`에는 `glfwGetFramebufferSize()`가 돌려준 크기를 사용한다.

**확인:** 좌우 구분선을 `x=440`에 그려서 배치 영역이 의도대로 나뉘는지 본다.

## 3. 도형의 종류와 개별 조각을 구분한다

[`ShapeNumber`](../1-4/1-4/1-10.cpp#L26)는 **서로 맞는 도형인지** 판단하는 번호다.

| 값 | 의미 |
| --- | --- |
| `Square` | 사각형 |
| `EquilateralUp`, `EquilateralRight`, `EquilateralDown`, `EquilateralLeft` | 네 방향의 정삼각형 |
| `RightTopRight`, `RightBottomLeft` | 대각선 사각형을 이루는 두 직각삼각형 |

`Square = 1` 뒤의 값들은 차례대로 증가한다. 도형의 방향도 번호에 포함한다. 과제에 회전 키가 없으므로, 오른쪽을 향하는 삼각형은 처음부터 오른쪽을 향한 조각으로 만든다.

같은 `ShapeNumber`를 가진 조각은 여러 개 있을 수 있다. 예를 들어 사각형 조각 여섯 개가 모두 `ShapeNumber::Square`여도 된다. **개별 조각 하나**는 `pieces` 배열의 `pieceIndex`로 구별한다.

이때 사용하는 자료 구조는 다음과 같다.

```cpp
struct Piece
{
    ShapeNumber shapeNumber = ShapeNumber::Square;
    Point position;
    Color color;
    int boardIndex = -1;
    int slotIndex = -1;
};

struct TargetSlot
{
    ShapeNumber shapeNumber = ShapeNumber::Square;
    int pieceIndex = -1;
};

struct Board
{
    BoardType type = BoardType::FourSquares;
    std::vector<TargetSlot> slots;
    bool completed = false;
};
```

[`Piece`](../1-4/1-4/1-10.cpp#L59)는 움직이는 조각 하나, [`TargetSlot`](../1-4/1-4/1-10.cpp#L68)은 조각 하나가 들어갈 칸, [`Board`](../1-4/1-4/1-10.cpp#L74)는 여러 칸을 가진 모양판이다. `Point`는 `x, y`, `Color`는 `red, green, blue`를 묶는다.

`-1`은 **연결되지 않음**을 뜻한다.

- `piece.boardIndex == -1`: 조각이 어떤 모양판에도 붙지 않았다.
- `piece.slotIndex == -1`: 들어간 칸이 없다.
- `slot.pieceIndex == -1`: 목표 칸이 비어 있다.
- `dragState.selectedPieceIndex == -1`: 마우스로 집은 조각이 없다.

`std::vector<Piece> pieces`는 모든 조각의 목록이고 `std::vector<Board> boards`는 모든 모양판의 목록이다. 이 게임은 실행 중 조각을 배열에서 삭제하지 않으므로, 배열 인덱스를 연결 번호로 사용할 수 있다. `std::vector`는 여러 원소를 저장하는 C++ 표준 컨테이너다.

**확인:** 디버거에서 처음 생성한 조각은 `boardIndex == -1`, 처음 생성한 칸은 `pieceIndex == -1`인지 확인한다.

## 4. 도형의 꼭짓점을 계산한다

OpenGL은 “사각형을 그려라”라는 도형 이름만 받지 않는다. 실제 꼭짓점 좌표가 필요하다. [`GetShapeVertices()`](../1-4/1-4/1-10.cpp#L130)는 도형 번호와 기준 위치를 받아 꼭짓점 목록을 만든다.

한 변이 40인 사각형은 기준점에서 각 방향으로 20씩 떨어진 네 점을 사용한다.

```text
기준점 (100, 100)
왼쪽 위  (80, 80)      오른쪽 위 (120, 80)
왼쪽 아래(80, 120)     오른쪽 아래(120, 120)
```

함수는 먼저 `(-20, -20)`, `(20, -20)` 같은 **기준점 주변 상대 좌표**를 만들고, 마지막에 각 꼭짓점에 `(100, 100)`을 더한다. 기준 위치만 바꾸면 똑같은 도형을 다른 곳에 그릴 수 있다.

정삼각형의 높이는 [`EquilateralHeight()`](../1-4/1-4/1-10.cpp#L106)에서 구한다.

```text
높이 = 한 변 × √3 ÷ 2
     = 40 × √3 ÷ 2
     ≈ 34.64
```

위쪽을 향한 정삼각형 하나의 꼭짓점을 만든 뒤, 다른 방향은 90도씩 회전시킨다. 한 번 회전할 때 상대 좌표 `(x, y)`는 `(-y, x)`가 된다. 현재 화면은 아래쪽이 양의 Y축이므로, 화면상에서는 시계 방향으로 돈 것처럼 보인다.

직각삼각형 두 종류는 같은 너비 40·높이 80의 사각형을 대각선으로 나눈 양쪽 절반이다. 서로 같은 기준 위치에 놓아도 내부가 겹치지 않고 대각선 변을 공유한다.

**중요:** 이 꼭짓점 계산을 그리기와 클릭 판정에 모두 사용한다. 화면에서 보이는 경계와 실제 클릭 가능한 경계가 같아진다.

**확인:** 도형별로 꼭짓점 순서대로 외곽선만 그려 보고, 사각형·네 방향 정삼각형·두 직각삼각형이 기대한 모양인지 확인한다.

## 5. 모양판의 위치와 구성 칸을 정한다

[`CreateBoards()`](../1-4/1-4/1-10.cpp#L271)는 다섯 모양판에 어떤 조각 번호가 필요한지 등록한다.

| 모양판 | 필요한 조각 | 출처 |
| --- | --- | --- |
`FourSquares` | 사각형 4개 | 과제 그림 |
`FourTriangles` | 아래·오른쪽·위·왼쪽 정삼각형 각 1개 | 과제 그림 |
`DiagonalRectangle` | 서로 보완하는 직각삼각형 2개 | 과제 그림 |
`House` | 사각형 1개, 위쪽 정삼각형 1개 | 추가 모양판 |
`Arrow` | 사각형 1개, 오른쪽 정삼각형 1개 | 추가 모양판 |

`CreateBoards()`에는 조각의 **종류와 칸 개수**가 들어간다. 칸 위치는 별도로 [`GetBoardPosition()`](../1-4/1-4/1-10.cpp#L205)과 [`GetSlotPosition()`](../1-4/1-4/1-10.cpp#L212)이 계산한다.

모양판 번호를 `boardIndex`라 할 때 열은 `boardIndex % 2`, 행은 `boardIndex / 2`다. 그 결과 다섯 중심 위치는 `(610,140)`, `(895,140)`, `(610,360)`, `(895,360)`, `(610,580)`이다.

첫 번째 모양판의 사각형 4개는 중심에서 왼쪽·오른쪽, 위·아래로 22픽셀씩 떨어진다. 사각형 너비 40픽셀에 4픽셀 틈을 둔 셈이다. 첫 번째 칸의 중심은 `(610-22, 140-22) = (588,118)`이다.

네 방향 정삼각형은 각 끝이 모양판 중심을 향한다. 대각선 사각형의 두 직각삼각형은 **목표 기준 위치가 동일**하지만, 꼭짓점 모양이 달라 사각형의 서로 다른 절반을 채운다. 집에서는 지붕 밑변과 몸통 윗변이 닿고, 화살표에서는 삼각형 밑변과 사각형 오른쪽 변이 닿는다.

`GetSlotPosition()`을 빈 칸 외곽선, 붙일 위치 검사, 붙은 조각의 그리기에 함께 사용해야 위치가 어긋나지 않는다.

**확인:** 오른쪽에 빈 목표 칸의 외곽선 5종이 과제 그림과 추가 모양대로 나오는지 확인한다.

## 6. 필요한 조각을 먼저 만들고, 여분을 무작위로 추가한다

[`CreatePieces()`](../1-4/1-4/1-10.cpp#L307)는 모든 모양판의 모든 칸을 살펴보면서 **칸 하나에 맞는 조각 하나**를 먼저 만든다. 필요한 최소 수량은 `4 + 4 + 2 + 2 + 2 = 14개`다.

그다음 도형 번호 7종마다 `0~2개`의 여분을 무작위로 추가한다. 따라서 전체 조각 수는 14~28개다. 필요한 조각을 먼저 확보하므로 무작위 결과가 어떤 값이든 완성 가능하다. 난수 생성기는 `std::mt19937`이며 프로그램 실행 중 상태를 유지한다.

[`PlacePiecesRandomly()`](../1-4/1-4/1-10.cpp#L347)는 왼쪽 영역에 `6열 × 8행 = 48개`의 후보 위치를 만든다. `std::shuffle()`로 순서를 섞고, 각 위치에 `-5~5`픽셀의 작은 흔들림을 준다. 여기서 “무작위 위치”는 화면의 모든 실수 좌표를 무제한으로 뽑는 뜻이 아니라 **후보 위치를 섞는 방식**이다.

격자를 사용하면 조각이 한곳에 몰리는 일을 줄일 수 있다. 다만 높이 80픽셀인 직각삼각형은 흔들림 때문에 이웃 행의 조각과 조금 겹칠 가능성이 있다. 현재 코드는 완전한 무겹침 배치를 보장하지 않는다.

**확인:** `r`을 여러 번 눌러 전체 조각 수와 왼쪽 배치가 달라지는지, 필수 조각이 빠지지 않는지 확인한다.

## 7. 셰이더를 준비한다

게임의 맞추기 규칙은 C++에서 처리한다. 셰이더에는 도형 번호가 필요하지 않다. C++이 **어디에 어떤 색으로 그릴지** 결정하고 셰이더가 이를 화면에 표시한다.

1. [`ReadShaderFile()`](../1-4/1-4/1-10.cpp#L807)이 [vertex.glsl](../1-4/1-4/vertex.glsl)과 [fragment.glsl](../1-4/1-4/fragment.glsl)을 문자열로 읽는다. 먼저 실행 작업 디렉터리에서 찾고, 실패하면 소스 파일 위치를 기준으로 다시 찾는다.
2. [`CompileShader()`](../1-4/1-4/1-10.cpp#L827)가 각 GLSL 코드를 컴파일한다. 실패하면 로그를 출력한다.
3. [`CreateShaderProgram()`](../1-4/1-4/1-10.cpp#L851)이 버텍스 셰이더와 프래그먼트 셰이더를 연결한다. 연결 실패도 확인한다.
4. `main()`이 VAO와 VBO를 생성하고, `Vertex` 구조체의 데이터를 읽는 방법을 설정한다.

`Vertex`에는 `x, y, red, green, blue` 실수 다섯 개가 들어간다. `glVertexAttribPointer(0, 2, ...)`는 앞의 두 실수를 위치(`location = 0`)로 읽는다. `glVertexAttribPointer(1, 3, ...)`는 두 실수 뒤에서 시작하는 세 실수를 색상(`location = 1`)으로 읽는다.

**VBO**에는 정점 값들이 들어가고, **VAO**는 위치·색상을 어디서 어떻게 읽는지 기록한다. `glBufferData()`는 정점 값을 VBO로 전달한다. 실제 그리기는 `glDrawArrays()`가 시작한다.

버텍스 셰이더는 창 좌표를 OpenGL 화면 좌표로 변환한다.

```text
변환된 x = x ÷ 창 너비 × 2 - 1
변환된 y = 1 - y ÷ 창 높이 × 2
```

창 중앙 `(540,360)`은 `(0,0)`으로 바뀐다. 프래그먼트 셰이더는 정점에서 받은 RGB에 알파값 `1.0`을 더해 도형의 색상을 출력한다.

**확인:** GLSL 파일을 찾지 못하거나 문법이 틀렸을 때 오류 로그가 나오는지 확인한다. 정상일 때는 색상 있는 삼각형 하나부터 그려 본다.

## 8. 기본 그리기 함수를 조립해 전체 장면을 만든다

[`AddVertex()`](../1-4/1-4/1-10.cpp#L689)는 위치와 색상을 `Vertex`로 만든다. [`UploadVertices()`](../1-4/1-4/1-10.cpp#L695)는 정점 목록을 VBO로 보낸다.

- [`DrawFilledPolygon()`](../1-4/1-4/1-10.cpp#L701)은 내부를 채운다. 사각형은 삼각형 2개로 나누어 `GL_TRIANGLES`로 그린다.
- [`DrawOutline()`](../1-4/1-4/1-10.cpp#L715)은 `GL_LINE_LOOP`로 외곽선을 그린다.
- [`DrawLine()`](../1-4/1-4/1-10.cpp#L725)은 왼쪽과 오른쪽의 구분선 등을 그린다.
- [`DrawBoard()`](../1-4/1-4/1-10.cpp#L734)은 패널과 아직 비어 있는 목표 칸을 그린다. 완성된 패널은 초록빛으로 바뀐다.
- [`DrawPiece()`](../1-4/1-4/1-10.cpp#L769)은 조각을 색으로 채우고 외곽선을 그린다. 선택 중인 조각의 외곽선은 노란색이다.

[`DrawScene()`](../1-4/1-4/1-10.cpp#L781)은 `glUseProgram()`으로 셰이더를 선택하고 창 크기를 `glUniform2f()`로 보낸 다음 VAO/VBO를 바인딩한다. 그 후 구분선, 모양판, 일반 조각, 선택 중인 조각 순서로 그린다. 선택 중인 조각을 맨 마지막에 그리므로 다른 조각 위에 보인다.

**확인:** 빈 칸은 연한 외곽선, 조각은 진한 채움, 선택된 조각은 노란 외곽선으로 보이는지 확인한다.

## 9. 실제 도형 내부를 클릭했는지 판단한다

삼각형의 외접 사각형만 검사하면 삼각형 바깥 빈 부분을 클릭해도 선택된다. [`IsPointInsidePiece()`](../1-4/1-4/1-10.cpp#L431)는 실제 꼭짓점과 각 변을 사용한다.

[`CrossProduct()`](../1-4/1-4/1-10.cpp#L425)는 변과 마우스 위치가 만드는 방향을 계산한다.

```text
(변의 x 차이 × 점의 y 차이)
− (변의 y 차이 × 점의 x 차이)
```

현재 도형은 볼록한 삼각형·사각형이다. 모든 변에 대해 계산한 부호가 같은 방향이면 내부다. 양수와 음수가 모두 나오면 바깥이다. 값이 `0`인 경계 위의 점은 내부로 받아들인다.

[`FindTopPiece()`](../1-4/1-4/1-10.cpp#L458)는 `pieces`의 뒤쪽부터 클릭 여부를 검사한다. 조각을 배열의 앞쪽부터 그리므로, 뒤쪽에 있는 조각이 화면에서 앞에 보인다. 완성된 모양판에 속한 조각은 [`IsPieceLocked()`](../1-4/1-4/1-10.cpp#L452)가 제외한다.

**확인:** 삼각형의 빈 모서리 부분을 클릭해도 선택되지 않는지, 겹친 조각 중 앞에 보이는 조각이 선택되는지 확인한다.

## 10. 마우스를 눌러 조각을 움직인다

[`MouseButtonCallback()`](../1-4/1-4/1-10.cpp#L634)은 왼쪽 버튼을 눌렀을 때 조각을 찾고, **클릭 위치와 조각 기준점의 차이**를 `dragState.mouseOffset`에 저장한다.

```text
조각 기준점 = (100,100)
처음 클릭한 위치 = (110,105)
저장할 차이 = (10,5)
```

이후 커서가 `(200,200)`으로 움직이면 조각 기준점을 `(190,195)`로 옮긴다. 처음 클릭한 조각 내부 지점이 계속 커서를 따라간다. 차이를 저장하지 않으면 클릭하는 순간 조각 중심이 마우스 위치로 튄다.

[`CursorPositionCallback()`](../1-4/1-4/1-10.cpp#L668)은 [`MoveSelectedPiece()`](../1-4/1-4/1-10.cpp#L620)를 호출한다. 이동 전후에는 [`ClampPiecePosition()`](../1-4/1-4/1-10.cpp#L470)이 도형 꼭짓점의 최소·최대 좌표를 검사해 창 밖으로 나가지 않게 한다. 현재 제한 영역은 **창 전체**다. 오른쪽에서 잘못 놓은 조각도 다시 집을 수 있다.

이미 칸에 붙은 조각을 누르면 [`DetachPiece()`](../1-4/1-4/1-10.cpp#L498)가 연결을 해제한다. 먼저 현재 화면에 보이는 위치를 `piece.position`에 복사하고, 그다음 조각과 칸의 연결 번호를 `-1`로 바꾼다. 순서를 거꾸로 하면 조각이 이전의 자유 위치로 돌아갈 수 있다.

마우스를 놓을 때는 마지막 커서 위치로 조각을 갱신한 뒤 맞는 칸이 있는지 검사한다.

**확인:** 클릭할 때 조각이 튀지 않는지, 화면 끝에서 조각이 잘리지 않는지, 완성 전 붙인 조각을 다시 집을 수 있는지 확인한다.

## 11. 같은 번호의 가까운 칸에 조각을 붙인다

[`FindMatchingSlot()`](../1-4/1-4/1-10.cpp#L513)은 모든 모양판의 칸을 순회한다. 후보가 되려면 다음 네 조건을 모두 만족해야 한다.

1. 모양판이 아직 완성되지 않았다.
2. 칸에 다른 조각이 들어 있지 않다.
3. 조각과 칸의 `shapeNumber`가 같다.
4. 조각 기준점이 목표 칸 기준점에서 28픽셀 이내다.

여러 칸이 후보라면 가장 가까운 칸을 선택한다. 거리는 제곱으로 비교한다.

```cpp
distanceSquared = differenceX * differenceX
                + differenceY * differenceY;
```

허용 거리 28픽셀의 제곱은 `784`다. 제곱끼리 비교하면 매번 제곱근을 구할 필요가 없다.

예를 들어 첫 사각형 칸 중심이 `(588,118)`이고 조각 중심이 `(600,130)`이라면 차이는 `(12,12)`, 거리 제곱은 `12² + 12² = 288`이다. `288 ≤ 784`이므로 같은 번호이고 빈 칸이라면 붙는다.

[`TryAttachPiece()`](../1-4/1-4/1-10.cpp#L573)는 칸을 찾지 못하면 `false`를 반환한다. 이 경우 조각은 놓은 위치에 남는다. 찾으면 [`AttachPiece()`](../1-4/1-4/1-10.cpp#L563)가 조각에는 `boardIndex`와 `slotIndex`를, 칸에는 `pieceIndex`를 기록한다.

붙은 조각의 실제 화면 위치는 [`GetPiecePosition()`](../1-4/1-4/1-10.cpp#L262)이 목표 칸에서 가져온다. 그래서 손으로 조금 어긋나게 놓아도 목표 위치에 정확히 붙어 보인다.

**확인:** 번호가 다른 칸·이미 채운 칸·멀리 떨어진 칸에는 붙지 않는지 확인한다. 가까운 같은 번호의 빈 칸에는 정확히 붙어야 한다.

## 12. 완성 판정과 잠금을 적용한다

[`CheckBoardCompleted()`](../1-4/1-4/1-10.cpp#L551)은 조각을 붙인 뒤 해당 모양판의 모든 칸을 검사한다. `std::all_of()`는 모든 칸의 `pieceIndex >= 0`일 때 `true`를 반환한다.

완성 전에는 붙은 조각을 다시 선택하고 이동할 수 있다. 마지막 칸이 채워지면 `board.completed = true`가 된다. 그 순간부터 `FindTopPiece()`가 해당 모양판의 조각을 선택 대상에서 제외한다. 모든 모양판이 완성되면 창 제목에 `Complete!`가 표시된다.

**확인:** 마지막 조각을 올리기 전에는 재이동이 가능하고, 마지막 조각을 올린 뒤에는 그 모양판의 모든 조각이 움직이지 않는지 확인한다.

## 13. 초기화 키와 종료 키를 연결한다

[`KeyCallback()`](../1-4/1-4/1-10.cpp#L673)은 키를 누른 순간인 `GLFW_PRESS`에서만 반응한다.

- `R`: [`ResetGame()`](../1-4/1-4/1-10.cpp#L415) 호출
- `Q`: `glfwSetWindowShouldClose()` 호출

`ResetGame()`은 `dragState`를 비우고 모양판·조각·랜덤 배치를 다시 만든다. 조각을 잡은 상태에서 `R`을 눌러도 이전 조각 인덱스가 새 목록을 가리키지 않는다. `Q`는 직접 자원을 지우는 대신 창의 종료 플래그를 설정한다. 메인 반복문이 종료되고 정리 코드가 실행된다.

**확인:** 조각을 잡은 채 `R`을 눌러도 오류가 없는지, 완성 후 `R`을 누르면 잠금이 풀린 새 게임이 시작되는지 확인한다.

## 14. 상태 검증과 수동 점검을 한다

[`ValidateGameState()`](../1-4/1-4/1-10.cpp#L370)은 Debug 빌드에서 조각과 칸의 연결 번호가 서로 일치하는지 `assert`로 확인한다. [`RunPlacementSelfCheck()`](../1-4/1-4/1-10.cpp#L584)은 프로그램 시작 시 필수 조각으로 모양판 5개를 전부 채워 보고 잠금까지 확인한다. 검사가 끝나면 `ResetGame()`으로 실제 플레이용 새 게임을 만든다.

`#ifndef NDEBUG` 내부의 검사는 Release 빌드에서 제외된다. `assert`는 개발 중 잘못된 상태를 빠르게 찾는 도구다. Release에서 반드시 실행해야 하는 게임 동작을 `assert`에 의존하게 만들면 안 된다.

수동으로는 다음 순서가 유용하다.

1. 왼쪽에 세 종류의 조각이 보이는지 확인한다.
2. 과제 그림의 목표 모양판 3개와 추가 모양판 2개가 보이는지 확인한다.
3. 삼각형의 실제 내부를 클릭할 때만 선택되는지 확인한다.
4. 번호가 다른 칸에 놓았을 때 붙지 않는지 확인한다.
5. 맞는 칸에 가까이 놓았을 때 정확히 붙는지 확인한다.
6. 완성 전 붙은 조각을 다시 움직일 수 있는지 확인한다.
7. 완성 후 해당 모양판의 조각을 움직일 수 없는지 확인한다.
8. 드래그 중 `R`, 여러 번의 초기화, `Q` 종료를 확인한다.

컴파일 성공과 짧은 실행 점검만으로 마우스 조작의 화면상 동작까지 검증한 것은 아니다. 실제 창에서 위 항목을 확인해야 한다.

## 전체 흐름: 사각형 한 조각을 놓는 예

첫 번째 모양판의 첫 칸을 채운다고 가정하자.

1. `CreateBoards()`가 그 칸에 필요한 번호를 `ShapeNumber::Square`로 기록한다.
2. `CreatePieces()`가 그 번호의 사각형 조각을 최소 한 개 확보한다.
3. `PlacePiecesRandomly()`가 그 조각을 왼쪽의 무작위 후보 위치에 둔다.
4. `DrawScene()`이 왼쪽 조각과 오른쪽 빈 칸 외곽선을 그린다.
5. 마우스를 누르면 `FindTopPiece()`가 조각을 선택하고 클릭 위치 차이를 기록한다.
6. 커서를 움직이면 `MoveSelectedPiece()`가 조각 위치를 바꾼다.
7. 마우스를 놓으면 `FindMatchingSlot()`이 같은 번호의 비어 있는 가까운 칸을 찾는다.
8. `AttachPiece()`가 조각과 칸의 연결 번호를 양쪽에 기록한다.
9. 이후 `GetPiecePosition()`은 자유 위치 대신 목표 칸 위치를 반환한다.
10. 마지막 빈 칸까지 채우면 `CheckBoardCompleted()`가 모양판을 잠근다.

화면에 조각이 보이지 않으면 **그리기 단계**, 클릭이 되지 않으면 **선택 단계**, 붙지 않으면 **번호·거리 판정 단계**, 완성 후에도 움직이면 **완성·잠금 단계**부터 확인한다.

# 2부. 실제 코드를 한 줄씩 읽고 바꿔 보기

앞의 1부는 기능을 만드는 순서였다. 여기서는 같은 순서를 따라가며 **실제 코드의 핵심 줄이 하는 일**과 **그 줄을 수정했을 때의 결과**를 확인한다. 코드는 설명에 필요한 부분만 발췌했다. 발췌문만 따로 붙여 넣으면 컴파일되지 않을 수 있으므로 반드시 링크된 원본 함수의 앞뒤 문맥도 함께 읽는다. 값을 바꾸는 연습은 한 번에 하나만 바꾸고, 실행 결과를 확인한 뒤 원래 값으로 돌리는 편이 원인 파악에 좋다.

## 15. 창 초기화 코드: 순서를 바꾸면 무엇이 달라질까?

[`main()`의 초기화 부분](../1-4/1-4/1-10.cpp#L891)에서 먼저 `glfwInit()`을 검사한다. 반환값이 거짓이면 창을 만들 수 없으므로 `return -1`로 끝낸다. 여기서 실패 검사를 제거하면 GLFW 초기화 실패 후에도 창 생성 코드가 실행된다. 오류가 발생한 지점을 찾기 어려워진다.

| 실제 줄 | 현재 역할 | 수정했을 때의 결과 |
| --- | --- | --- |
| `glfwWindowHint(GLFW_CONTEXT_VERSION_MAJOR, 3);` | OpenGL 주 버전을 3으로 요청한다. | 값을 바꾸면 요청하는 OpenGL 버전이 바뀐다. 사용하는 셰이더 버전과 컴퓨터의 지원 여부도 함께 확인해야 한다. |
| `glfwWindowHint(GLFW_CONTEXT_VERSION_MINOR, 3);` | OpenGL 부 버전을 3으로 요청한다. 두 줄을 합쳐 3.3이다. | `0`으로 바꾸면 3.0을 요청하게 된다. 현재 `#version 330 core`와 맞지 않을 수 있다. |
| `glfwWindowHint(GLFW_OPENGL_PROFILE, GLFW_OPENGL_CORE_PROFILE);` | Core Profile을 요청한다. | 호환성 프로필로 바꾸면 허용되는 옛 API가 달라진다. 현재 코드는 VAO/VBO·셰이더를 사용하므로 프로필 변경이 기능 추가를 대신하지는 않는다. |
| `glfwWindowHint(GLFW_RESIZABLE, GLFW_FALSE);` | 사용자가 창 크기를 바꾸지 못하게 한다. | `GLFW_TRUE`로 바꾸면 창은 늘어나지만 현재 좌표·`windowSize`는 고정 값이다. 모양판 배치와 입력 좌표를 함께 수정해야 한다. |
| `glfwCreateWindow(WINDOW_WIDTH, WINDOW_HEIGHT, ...)` | 상수로 정한 크기의 창을 만든다. | 상수의 값을 바꾸면 창 크기가 바뀐다. 오른쪽 모양판의 고정 위치와 왼쪽 조각 격자가 창 안에 들어오는지도 다시 계산해야 한다. |
| `glfwMakeContextCurrent(window);` | 이후 OpenGL 호출이 사용할 컨텍스트를 활성화한다. | `glewInit()` 뒤로 옮기면 GLEW 초기화 시 필요한 컨텍스트가 준비되지 않는다. |
| `glfwSwapInterval(1);` | 화면 교체를 수직 동기화에 맞추도록 요청한다. | `0`으로 바꾸면 동기화를 요청하지 않는다. 화면 찢김이 보이거나 CPU 사용이 늘 수 있다. |

`glewExperimental = GL_TRUE`와 `glewInit()`은 컨텍스트를 만든 다음에 있다. GLFW는 창·입력을 제공하고, GLEW는 OpenGL 함수 사용을 준비한다. 서로 역할이 다르다.

창 크기는 논리 좌표와 실제 프레임버퍼에서 다를 수 있다. [`glfwGetFramebufferSize()`와 `glViewport()`](../1-4/1-4/1-10.cpp#L934)는 실제 그리기 영역을 설정한다. 프레임버퍼 크기 콜백을 삭제하면 화면 배율이나 프레임버퍼 크기 변화에 뷰포트가 맞지 않을 수 있다.

## 16. 상수 한 줄을 바꾸면 영향이 어디까지 퍼질까?

[상수 선언](../1-4/1-4/1-10.cpp#L17)은 단순한 장식이 아니다. 여러 함수가 같은 값을 읽으므로 **한 줄 변경이 여러 동작을 동시에 바꾼다.**

| 상수 | 현재 사용처 | 예를 들어 바꾸면 |
| --- | --- | --- |
| `WINDOW_WIDTH = 1080` | 창 생성, 창 경계 제한, 셰이더 `windowSize` | 900으로 줄이면 오른쪽 두 번째 열의 모양판 중심 `x=895`와 패널 오른쪽 끝이 창 밖으로 나간다. 모양판 위치도 수정해야 한다. |
| `WINDOW_HEIGHT = 720` | 창 생성, 조각 경계 제한, 셰이더 `windowSize`, 구분선 | 600으로 줄이면 아래쪽 모양판 중심 `y=580`과 왼쪽 격자의 아래쪽 조각이 잘릴 수 있다. |
| `LEFT_AREA_WIDTH = 440` | 좌우 구분선을 그리는 위치 | 500으로 바꾸면 **선만** `x=500`으로 이동한다. 왼쪽 랜덤 조각 격자와 오른쪽 모양판 위치는 자동으로 이동하지 않는다. |
| `PIECE_SIZE = 40` | 사각형·정삼각형 꼭짓점, 목표 칸 간격 | 60으로 늘리면 도형이 커지고 목표 칸 간격도 바뀐다. 왼쪽 격자 간격, 모양판 패널 크기, 집·화살표가 패널 안에 드는지 재확인해야 한다. |
| `RIGHT_TRIANGLE_HEIGHT = 80` | 두 직각삼각형의 위아래 꼭짓점 | 40으로 줄이면 대각선 모양판은 높이 40인 사각형이 된다. 클릭 판정 영역도 같이 바뀐다. |
| `SNAP_DISTANCE = 28` | 조각이 칸에 붙는 거리 판정 | 8로 줄이면 정확히 가까이 놓아야 한다. 50으로 늘리면 멀리서도 붙어 쉬워지지만, 가까운 다른 칸을 잘못 선택할 여지가 커진다. |
| `BOARD_COUNT = 5` | Debug 상태 검사 | 숫자만 6으로 바꾸면 실제 `CreateBoards()`는 5개를 만들므로 Debug `assert`가 실패한다. 새 모양판 정의도 추가해야 한다. |

`WINDOW_WIDTH`를 바꾸고 `glUniform2f()`에 전달하는 크기를 옛 값으로 고정하면, 셰이더의 픽셀 좌표 변환이 틀어져 그린 위치와 마우스 좌표가 어긋난다. 현재 코드는 같은 상수를 전달하므로 함께 바뀐다.

## 17. 구조체 필드를 바꾸면 게임 상태가 어떻게 달라질까?

[`Piece`, `TargetSlot`, `Board`, `DragState`](../1-4/1-4/1-10.cpp#L59)의 필드는 서로 연결되어 있다. 한 필드의 뜻을 바꾸면 그 값을 읽는 함수도 확인해야 한다.

| 필드 | 정확한 역할 | 제거·변경하면 |
| --- | --- | --- |
| `Piece::shapeNumber` | 조각이 어느 종류·방향인지 나타낸다. | `TargetSlot::shapeNumber`와 비교할 수 없어 번호 기반 합체 판정이 사라진다. |
| `Piece::position` | 모양판에 연결되지 않은 조각의 기준 위치다. | 값을 바꾸면 자유 조각의 표시 위치와 드래그·거리 판정이 같이 바뀐다. 연결된 조각은 `GetPiecePosition()`이 칸 위치를 대신 반환한다. |
| `Piece::boardIndex`, `slotIndex` | 조각이 들어간 모양판과 칸의 인덱스다. | 둘 중 하나만 갱신하면 조각이 어느 칸에 붙었는지 추적할 수 없다. 디버그 검증도 실패한다. |
| `TargetSlot::shapeNumber` | 그 칸이 요구하는 도형 번호다. | 번호를 바꾸면 다른 종류의 조각을 요구한다. 그림 외곽선의 모양도 함께 바뀐다. |
| `TargetSlot::pieceIndex` | 그 칸을 차지한 개별 조각의 인덱스다. | 채워진 칸을 빈 칸으로 잘못 판단하거나, 다른 조각이 같은 칸을 차지할 수 있다. |
| `Board::completed` | 해당 모양판 전체가 완성됐는지 기억한다. | `true`가 되면 그 모양판의 조각은 선택되지 않고 패널이 초록색으로 그려진다. |
| `DragState::selectedPieceIndex` | 지금 움직이는 조각의 인덱스다. | 마우스를 놓기 전에 `-1`로 만들면 현재 선택 조각을 찾을 수 없다. |
| `DragState::mouseOffset` | 처음 클릭한 지점과 조각 기준점의 차이다. | `(0,0)`으로 고정하면 클릭 즉시 조각 기준점이 커서로 이동해 조각이 튄다. |

`int boardIndex = -1`의 `-1`은 유효한 배열 번호가 아니다. 따라서 **미연결 상태**를 나타내는 데 쓴다. `0`을 기본값으로 바꾸면 모든 새 조각이 첫 번째 모양판에 붙은 것처럼 해석될 수 있다.

[`Vertex`](../1-4/1-4/1-10.cpp#L87)는 게임 규칙용 구조체가 아니라 GPU로 보낼 정점 형식이다. 필드 순서가 `x, y, red, green, blue`다. 예를 들어 `red`를 `x` 앞으로 옮기면 `glVertexAttribPointer()`의 오프셋도 바꿔야 한다. 그렇지 않으면 GPU가 색상을 위치로 읽어 도형이 잘못 그려진다.

## 18. 꼭짓점 공식의 각 줄을 따라간다

[`GetShapeVertices()`](../1-4/1-4/1-10.cpp#L130) 첫 부분의 `halfSize = PIECE_SIZE / 2.0f`는 도형을 기준점 중심으로 만들기 위해 필요하다. `PIECE_SIZE`가 40이면 `halfSize`는 20이다.

| 코드 | 현재 의미 | 수정하면 |
| --- | --- | --- |
| `{ -halfSize, -halfSize }` | 사각형의 왼쪽 위 상대 좌표다. | 첫 성분을 `0`으로 바꾸면 왼쪽 변만 오른쪽으로 이동해 사각형이 찌그러진다. 클릭 영역도 같은 모양으로 바뀐다. |
| `{ 0.0f, -2.0f * height / 3.0f }` | 위쪽 정삼각형의 꼭대기다. | `-height`로 바꾸면 기준점에 대한 위치가 달라져 집 지붕과 몸통의 접점이 어긋난다. 다른 두 점과의 거리도 다시 확인해야 한다. |
| `{ -halfSize, height / 3.0f }`, `{ halfSize, height / 3.0f }` | 정삼각형 밑변의 양 끝이다. | 한쪽 부호만 바꾸면 두 밑변 점이 같은 쪽으로 모이거나 삼각형 폭이 바뀐다. |
| `vertex.x = -vertex.y; vertex.y = previousX;` | 정삼각형 꼭짓점을 90도 회전한다. | `previousX` 대신 이미 바뀐 `vertex.x`를 사용하면 원래 X가 사라져 정확한 회전이 되지 않는다. |
| `vertex.x += position.x; vertex.y += position.y;` | 상대 좌표를 실제 화면 좌표로 옮긴다. | 더하기를 빼기로 바꾸면 조각이 기준 위치와 반대 방향으로 이동해 드래그와 목표 칸이 어긋난다. |

정삼각형 꼭짓점의 Y 좌표를 `-2h/3`, `h/3`, `h/3`로 둔 이유는 세 꼭짓점의 평균 Y가 0이 되게 하려는 것이다. 따라서 `position`이 삼각형의 기준 중심처럼 작동한다. 높이 `h ≈ 34.64`일 때 꼭대기는 기준점 위로 약 `23.09`, 밑변은 기준점 아래로 약 `11.55`다.

직각삼각형은 [`RightTopRight`와 `RightBottomLeft` 분기](../1-4/1-4/1-10.cpp#L179)의 꼭짓점 순서가 다르다. 둘을 같은 기준점에 놓으면 대각선이 왼쪽 위에서 오른쪽 아래로 이어지고, 내부는 서로 다른 절반을 채운다. 한쪽 꼭짓점만 임의로 바꾸면 틈이나 겹침이 생길 수 있다.

## 19. 모양판 위치 함수의 숫자를 바꾸면 어디가 움직일까?

[`GetBoardPosition()`](../1-4/1-4/1-10.cpp#L205)의 `boardIndex % 2`는 열 번호를 `0,1,0,1,0`으로 만들고, `boardIndex / 2`는 행 번호를 `0,0,1,1,2`로 만든다.

```cpp
return { 610.0f + column * 285.0f,
         140.0f + row * 220.0f };
```

`610`을 `650`으로 바꾸면 모든 모양판이 오른쪽으로 40픽셀 이동한다. `285`를 키우면 두 열 사이 간격만 넓어진다. `220`을 키우면 행 사이 간격이 넓어진다. 모양판은 창 경계와 패널 크기 `250 × 190` 안에 있어야 한다. 첫 열의 위치만 바꾸고 싶다면 이 단순 공식을 조정하거나 배치 방식을 변경해야 한다.

[`GetSlotPosition()`](../1-4/1-4/1-10.cpp#L212)은 모양판 중심에 `offset`을 더한다. 사각형 네 개의 `halfSpacing = (PIECE_SIZE + 4.0f) / 2.0f`에서 `4.0f`가 조각 사이 틈이다. `4`를 `0`으로 바꾸면 사각형들이 변을 맞대고, `20`으로 바꾸면 간격이 커진다.

`slotIndex % 2`는 왼쪽/오른쪽, `slotIndex < 2`는 위/아래를 결정한다. 칸 등록 순서를 바꿀 때 이 인덱스 규칙도 확인해야 한다. 네 방향 정삼각형은 인덱스 `0,1,2,3`에 각각 위·왼쪽·아래·오른쪽 위치를 준다. 그 인덱스에 등록한 `ShapeNumber`와 위치가 맞아야 꼭짓점이 중심을 향한다.

대각선 모양판은 두 칸의 `offset`이 모두 `(0,0)`인 상태로 끝난다. 이는 누락이 아니다. 두 직각삼각형이 같은 사각형 범위에서 서로 다른 절반을 차지하도록 의도한 것이다.

집 지붕의 `offset.y = -height / 3.0f`와 화살촉의 `offset.x = height / 3.0f`는 정삼각형의 밑변이 사각형 변에 닿는 위치다. 이 값만 바꾸면 접점에 틈이 생기거나 도형이 겹친다.

**한 군데에서 계산하는 이점:** `GetSlotPosition()`을 수정하면 빈 칸 외곽선, 스냅 판정, 붙은 조각의 그리기가 함께 새 위치를 사용한다. 위치를 여러 함수에 따로 적었다면 세 군데를 모두 고쳐야 한다.

## 20. 랜덤 생성 코드의 줄별 효과

[`CreatePieces()`](../1-4/1-4/1-10.cpp#L307)의 `pieces.clear()`는 이전 게임의 조각을 지운다. 이 줄을 제거한 채 `R`을 누르면 이전 조각이 남은 상태에서 새 조각이 계속 추가된다.

```cpp
for (const Board& board : boards)
{
    for (const TargetSlot& slot : board.slots)
    {
        Piece piece;
        piece.shapeNumber = slot.shapeNumber;
        pieces.push_back(piece);
    }
}
```

이중 반복의 바깥쪽은 모양판을, 안쪽은 각 모양판의 칸을 순회한다. 실제 코드에는 `piece.color = GetShapeColor(...)`도 있다. 조각을 먼저 만들지 않고 여분만 랜덤으로 생성하면 어떤 모양판에 필요한 종류가 부족할 수 있다.

| 코드 | 현재 역할 | 수정하면 |
| --- | --- | --- |
| `std::array<ShapeNumber, 7> shapeNumbers` | 여분을 만들 수 있는 도형 번호 7종을 열거한다. | 새 도형 번호를 `enum`에만 추가하고 배열에 빠뜨리면 그 도형의 여분은 생성되지 않는다. 배열 크기도 목록과 맞춰야 한다. |
| `std::uniform_int_distribution<int> extraCount(0, 2)` | 번호마다 여분을 0~2개 만든다. | `(0, 0)`이면 여분이 사라져 항상 최소 14개다. `(3, 5)`면 왼쪽이 복잡해지고 48개 후보 자리를 초과할 가능성도 확인해야 한다. |
| `std::shuffle(positions.begin(), positions.end(), randomGenerator)` | 후보 자리의 순서를 무작위로 섞는다. | 제거하면 조각이 매번 격자의 앞자리부터 차례대로 배치되어 위치 변화가 작아진다. |
| `jitter(-5.0f, 5.0f)` | 선택된 격자 자리에서 약간 움직이게 한다. | `(0, 0)`이면 모든 조각이 정확한 격자 중심에 놓인다. 범위를 크게 늘리면 조각끼리 겹치거나 영역 밖으로 나갈 수 있다. |
| `assert(pieces.size() <= positions.size())` | Debug에서 조각 수가 후보 자리 48개 이하인지 확인한다. | 제거하면 조각 수가 48개를 넘는 수정 후 `positions[i]` 범위를 벗어날 수 있다. Release에서는 `assert`가 실행되지 않으므로 조각 수를 크게 늘릴 때 별도 처리가 필요하다. |

난수 생성기 `std::mt19937 randomGenerator(std::random_device{}())`는 전역에서 한 번 만들어진다. `R`을 누를 때마다 새 시드를 만드는 방식이 아니다. 같은 실행 중에도 난수 생성기의 상태가 계속 진행되므로 새로운 배치가 나온다.

## 21. GLSL 파일·VAO·VBO에서 바꾸면 안 되는 연결 고리

[`ReadShaderFile()`](../1-4/1-4/1-10.cpp#L807)은 먼저 `vertex.glsl` 같은 파일명을 현재 작업 디렉터리에서 연다. 실패하면 `__FILE__`이 가리키는 소스 파일의 부모 경로에서 다시 찾는다. `file.clear()`는 첫 열기 실패 상태를 지운다. 두 위치에서 모두 실패하면 오류를 출력하고 빈 문자열을 반환한다. GLSL 파일명을 바꾸면 읽는 문자열과 실제 파일명도 맞춰야 한다.

[`CompileShader()`](../1-4/1-4/1-10.cpp#L827)는 `glShaderSource()`로 문자열을 전달하고 `glCompileShader()`로 컴파일한다. `GL_COMPILE_STATUS`가 거짓이면 로그를 출력하고 셰이더 객체를 지운 후 `0`을 반환한다. `CreateShaderProgram()`은 두 셰이더 중 하나라도 `0`이면 연결을 시도하지 않는다. 이 실패 확인을 제거하면 실제 GLSL 오류 대신 나중의 빈 화면이나 연결 오류만 보게 될 수 있다.

두 셰이더가 성공하면 `glAttachShader()`로 프로그램에 붙이고 `glLinkProgram()`으로 연결한다. 연결 상태도 검사한다. 성공 후의 `glDeleteShader()`는 개별 셰이더 객체를 정리하는 호출이다. 연결된 프로그램 자체는 이후 `glUseProgram(shaderProgram)`으로 사용한다.

[`main()`의 VAO/VBO 설정](../1-4/1-4/1-10.cpp#L948)은 C++ 정점 형식과 GLSL 입력을 정확히 맞춘다.

| C++ 설정 | GLSL 입력 | 의미와 변경 효과 |
| --- | --- | --- |
| `glVertexAttribPointer(0, 2, ..., sizeof(Vertex), 0)` | `layout(location = 0) in vec2 position` | 정점 앞의 실수 2개를 좌표로 읽는다. `2`를 `1`로 바꾸면 Y 성분이 정점 버퍼에서 전달되지 않아 도형이 위쪽 선으로 찌그러진다. |
| `glVertexAttribPointer(1, 3, ..., sizeof(Vertex), 2*sizeof(float))` | `layout(location = 1) in vec3 color` | 좌표 두 실수를 건너뛰고 RGB 세 실수를 읽는다. 마지막 오프셋을 `0`으로 바꾸면 좌표 값이 색상처럼 해석된다. |
| `glEnableVertexAttribArray(0/1)` | 위치와 색상 입력 | 해당 속성 배열을 활성화한다. 하나를 빠뜨리면 그 속성의 버퍼 값이 셰이더로 정상 전달되지 않는다. |
| `glGetUniformLocation(shaderProgram, "windowSize")` | `uniform vec2 windowSize` | C++에서 값을 넣을 GLSL 입력 위치를 찾는다. 문자열 이름을 GLSL의 이름과 다르게 쓰면 위치를 찾지 못한다. |

[`vertex.glsl`](../1-4/1-4/vertex.glsl)의 `position / windowSize * 2.0 - 1.0`은 픽셀 좌표를 `-1~1` 범위로 바꾼다. 그다음 Y 부호를 뒤집어 화면 위쪽이 위로 보이게 한다. Y 반전을 지우면 위아래 배치가 뒤집혀 마우스로 본 위치와 다르게 보인다. [`fragment.glsl`](../1-4/1-4/fragment.glsl)의 `vec4(vertexColor, 1.0)`은 RGB에 알파 `1.0`을 붙인다. RGB 값 자체는 `GetShapeColor()`가 C++에서 정한다.

## 22. 그리기 함수의 매개변수를 바꾸면 화면이 어떻게 달라질까?

[`UploadVertices()`](../1-4/1-4/1-10.cpp#L695)의 `vertices.size() * sizeof(Vertex)`는 GPU로 보낼 **전체 바이트 수**다. `vertices.size()`만 전달하면 정점 개수만큼의 바이트를 보내게 되어 데이터가 잘린다. `vertices.data()`는 실제 정점 배열의 시작 주소다. `GL_DYNAMIC_DRAW`는 버퍼 내용을 자주 바꾸는 현재 사용 방식을 나타내는 힌트다.

[`DrawFilledPolygon()`](../1-4/1-4/1-10.cpp#L701)의 반복문은 첫 꼭짓점과 그 뒤의 이웃한 두 꼭짓점으로 삼각형을 만든다.

```text
삼각형 꼭짓점 3개: (0,1,2) 한 개
사각형 꼭짓점 4개: (0,1,2), (0,2,3) 두 개
```

그래서 `glDrawArrays(GL_TRIANGLES, 0, vertices.size())`가 사각형도 채운다. 이 방식은 현재 쓰는 볼록 도형에는 맞는다. 나중에 안쪽으로 파인 오목 다각형을 추가하면 같은 분할 방식이 항상 올바르지는 않다.

[`DrawOutline()`](../1-4/1-4/1-10.cpp#L715)의 `GL_LINE_LOOP`는 마지막 점과 첫 점까지 연결한다. `GL_LINE_STRIP`으로 바꾸면 마지막 닫는 선이 빠진다. [`DrawLine()`](../1-4/1-4/1-10.cpp#L725)의 `GL_LINES`는 독립된 두 점으로 선 하나를 그린다.

[`DrawBoard()`](../1-4/1-4/1-10.cpp#L734)의 `center.x ± 125`, `center.y ± 95`는 배경 패널 너비 250, 높이 190을 만든다. 숫자를 줄이면 내부 모양판이 패널 경계에 닿거나 밖으로 나갈 수 있다. `if (slot.pieceIndex >= 0) continue;`는 채운 칸의 연한 안내 외곽선을 그리지 않는다. 이 조건을 지우면 배치된 조각 아래에도 안내 선을 계속 그리지만, 조각을 나중에 그려 대부분 가려진다.

[`DrawScene()`](../1-4/1-4/1-10.cpp#L781)의 `glUseProgram(shaderProgram)`은 뒤따르는 `glUniform2f()`와 그리기가 사용할 프로그램을 선택한다. `glBindVertexArray(vao)`는 정점 읽기 규칙을 선택한다. `glBindBuffer(GL_ARRAY_BUFFER, vbo)`는 `UploadVertices()`가 내용을 바꿀 버퍼를 선택한다.

조각을 배열 앞에서 뒤로 그리고 선택 중인 조각을 마지막에 한 번 더 그리는 순서도 중요하다. 선택 중인 조각을 마지막에 그리지 않으면 다른 조각 뒤에 가려질 수 있다. 일반 조각의 그리기 순서를 뒤집는다면 `FindTopPiece()`의 클릭 검사 순서도 함께 검토해야 한다.

## 23. 클릭 판정의 부호와 검사 순서

[`CrossProduct()`](../1-4/1-4/1-10.cpp#L425)는 한 변 `a→b`에 대해 마우스 점이 어느 쪽에 있는지 부호로 알려 준다. [`IsPointInsidePiece()`](../1-4/1-4/1-10.cpp#L431)는 모든 변을 검사하면서 양수와 음수가 **둘 다** 등장하면 바깥으로 판단한다. 한쪽 부호만 있거나 0이면 내부 또는 경계다.

```cpp
hasPositive |= cross > 0.0f;
hasNegative |= cross < 0.0f;
if (hasPositive && hasNegative)
    return false;
```

`|=`는 기존 참/거짓 값과 새 비교 결과를 합친다는 뜻이다. 한 번 `true`가 되면 다음 변에서도 유지된다. `&&`를 `||`로 바꾸면 한쪽 부호만 나와도 바깥으로 판단해 정상적인 클릭이 막힌다. 경계값 `0`은 양수도 음수도 아니므로 현재는 경계를 클릭할 수 있다. 부동소수점 계산 때문에 경계 바로 근처에서는 판정이 민감할 수 있다.

[`FindTopPiece()`](../1-4/1-4/1-10.cpp#L458)는 마지막 조각부터 첫 조각으로 검사한다. `return i`는 처음 발견한 조각을 선택한다. 화면에 나중에 그린 조각이 위에 보이기 때문에 검사도 역순이다. `IsPieceLocked(i)` 검사를 없애면 완성된 모양판의 조각도 다시 집을 수 있다. 반대로 `piece.boardIndex >= 0`만으로 잠그면 **완성 전** 붙여 둔 조각까지 이동할 수 없게 된다.

## 24. 드래그 처리에서 순서가 중요한 줄

[`MouseButtonCallback()`](../1-4/1-4/1-10.cpp#L634)은 먼저 `button != GLFW_MOUSE_BUTTON_LEFT`이면 돌아간다. 이를 없애면 오른쪽 버튼 등에도 조각이 선택될 수 있다. `glfwGetCursorPos()`는 현재 커서 좌표를 `double`로 받고, 코드는 이를 `Point`의 `float`로 바꾼다.

누르는 순간의 순서는 **찾기 → 현재 위치 읽기 → 클릭 차이 저장 → 기존 연결 해제 → 선택 번호 저장**이다. 클릭 차이를 계산하기 전에 기존 연결을 잘못 지우면, 붙어 있던 조각의 현재 위치를 잃을 수 있다.

```cpp
dragState.mouseOffset = {
    mousePosition.x - piecePosition.x,
    mousePosition.y - piecePosition.y
};
```

이 뺄셈을 반대로 쓰면 커서가 움직일 때 조각 기준점을 계산하는 [`MoveSelectedPiece()`](../1-4/1-4/1-10.cpp#L620)의 `mousePosition - mouseOffset`과 짝이 맞지 않는다. 클릭 지점에서 조각이 튄다.

놓는 순간에는 `MoveSelectedPiece(mousePosition)`으로 **마지막 위치를 먼저 반영**하고, `TryAttachPiece(dragState.selectedPieceIndex)`로 칸을 찾은 다음, `selectedPieceIndex = -1`로 드래그를 끝낸다. 선택 번호를 먼저 `-1`로 바꾸면 다음 줄에 잘못된 인덱스가 전달될 수 있다.

[`ClampPiecePosition()`](../1-4/1-4/1-10.cpp#L470)은 조각의 기준점만 검사하지 않고 모든 꼭짓점의 최소·최대 X/Y를 계산한다. 기준점만 `0~1080`에 묶으면 기준점은 안에 있어도 삼각형 끝은 창 밖으로 나갈 수 있다. 창 밖으로 나간 크기만큼 위치를 되돌린다.

## 25. 번호와 거리 판정을 바꾸면 게임 난도가 어떻게 변할까?

[`FindMatchingSlot()`](../1-4/1-4/1-10.cpp#L513)에서 `matchingBoard`와 `matchingSlot`은 호출한 쪽으로 결과를 돌려주기 위해 참조(`&`)로 받는다. 함수 시작의 `-1` 초기화는 일치하는 칸을 아직 찾지 못했다는 표시다.

| 조건·계산 | 현재 역할 | 수정하면 |
| --- | --- | --- |
| `if (board.completed) continue;` | 완성된 모양판을 후보에서 제외한다. | 현재 정상 상태에서는 완성판의 빈 칸이 없어 제거해도 결과가 거의 같다. 완성 판정 규칙이 나중에 달라지면 완성판에 다시 조각을 붙일 수 있으므로 유지한다. |
| `slot.shapeNumber != piece.shapeNumber` | 같은 도형 번호만 받는다. | 제거하면 사각형을 삼각형 칸에 놓아도 붙을 수 있다. |
| `slot.pieceIndex >= 0` | 이미 채운 칸을 제외한다. | 제거하면 기존 조각 위에 새 조각을 연결해 양쪽 인덱스가 불일치할 수 있다. |
| `differenceX * differenceX + differenceY * differenceY` | 기준점 사이 거리의 제곱이다. | X 또는 Y 항을 빼면 한 방향으로는 얼마나 멀리 놓아도 붙을 수 있다. |
| `distanceSquared <= closestDistanceSquared` | 허용 거리 안에서 가장 가까운 칸을 갱신한다. | `<`로 바꾸면 정확히 경계 거리인 후보와 동점 처리 방식이 달라진다. 현재 `<=`는 같은 거리라면 나중에 순회한 칸을 선택한다. |
| `return matchingBoard >= 0` | 후보를 찾았는지 알린다. | 항상 `true`로 바꾸면 후보가 없을 때도 `-1` 인덱스로 `AttachPiece()`가 호출될 수 있다. |

[`AttachPiece()`](../1-4/1-4/1-10.cpp#L563)의 세 대입문은 하나의 동작이다. `Piece`에는 모양판·칸 번호를, `TargetSlot`에는 조각 번호를 기록한다. 한쪽만 기록하면 그리기·완성 판정·분리 동작이 서로 다른 상태를 보게 된다. 연결 직후 `CheckBoardCompleted()`와 `ValidateGameState()`를 호출하는 이유도 여기에 있다.

[`TryAttachPiece()`](../1-4/1-4/1-10.cpp#L573)가 `false`이면 조각을 원래 왼쪽 자리로 되돌리지 않는다. 마우스를 놓은 현재 위치에 자유 조각으로 남는다. 이 동작을 바꾸려면 드래그 시작 위치를 별도로 기억하고 실패 시 복원해야 한다.

## 26. 완성·초기화·검증 코드를 바꿀 때 주의할 점

[`CheckBoardCompleted()`](../1-4/1-4/1-10.cpp#L551)의 `std::all_of()`는 칸마다 `pieceIndex >= 0`인지 검사한다. 조건을 `> 0`으로 바꾸면 **0번 조각이 들어간 칸을 빈 칸으로 오판**한다. 배열의 첫 번째 인덱스는 0이므로 `>= 0`이어야 한다.

`Board::completed`는 패널 색상과 조각 잠금에 동시에 사용된다. `true`를 마지막 칸보다 일찍 설정하면 나머지 칸을 채우기 전에 판이 잠긴다. 완성 전 조각을 다시 집으면 [`DetachPiece()`](../1-4/1-4/1-10.cpp#L498)가 `completed = false`로 돌리고 칸의 `pieceIndex`를 비운다. 이미 완성된 모양판은 애초에 선택되지 않으므로 정상 입력으로는 분리되지 않는다.

[`ResetGame()`](../1-4/1-4/1-10.cpp#L415)의 순서는 **드래그 상태 초기화 → 모양판 생성 → 필수·여분 조각 생성 → 랜덤 배치 → 검증**이다. `CreatePieces()`를 `CreateBoards()`보다 먼저 호출하면 순회할 목표 칸이 없어서 필요한 조각이 만들어지지 않는다. `dragState = {}`를 빼면 초기화 이전의 선택 인덱스가 새 조각 목록을 가리킬 수 있다.

[`KeyCallback()`](../1-4/1-4/1-10.cpp#L673)은 `action != GLFW_PRESS`를 먼저 거른다. 이 조건을 없애면 키를 누르고 있는 동안의 반복 입력이나 키를 뗄 때에도 `ResetGame()`이 여러 번 실행될 수 있다. `GLFW_KEY_R`은 새 게임을 시작하고, `GLFW_KEY_Q`는 종료 플래그만 설정한다. 종료 시 자원 삭제는 메인 반복문 아래에서 진행한다.

[`ValidateGameState()`](../1-4/1-4/1-10.cpp#L370)는 Debug에서 연결 양쪽의 번호와 완성 상태가 일치하는지 검사한다. [`RunPlacementSelfCheck()`](../1-4/1-4/1-10.cpp#L584)는 시작할 때 필수 조각으로 다섯 판을 모두 채워 본 뒤 `ResetGame()`으로 실제 게임을 준비한다. 검사 코드가 `#ifndef NDEBUG` 안에 있으므로 Release에서는 빠진다. **Release에서도 반드시 실행돼야 하는 게임 규칙을 `assert(...)` 안으로 옮기지 않는다.**

## 27. 바꾸기 실습: 한 번에 한 줄씩

아래 순서로 바꾸면 역할을 눈으로 확인하기 쉽다. 각 실습 후에는 원래 값으로 돌리고 다음 실습을 한다.

1. `SNAP_DISTANCE`를 `28`에서 `8`로 바꾼다. 목표 칸에 훨씬 가깝게 놓아야 하는지 확인한다.
2. `extraCount(0, 2)`를 `extraCount(0, 0)`으로 바꾼다. 왼쪽 조각이 항상 필수 14개만 생성되는지 확인한다.
3. `jitter(-5.0f, 5.0f)`를 `jitter(0.0f, 0.0f)`로 바꾼다. 조각들이 정확한 격자 중심에 놓이는지 확인한다.
4. `FourSquares`의 간격 계산에서 `4.0f`를 `20.0f`로 바꾼다. 첫 모양판의 네 사각형 사이가 벌어지는지 확인한다.
5. `glClearColor(0.98f, 0.98f, 0.99f, 1.0f)`에서 RGB 값을 바꾼다. 배경만 바뀌고 조각 색은 유지되는지 확인한다.
6. `GetShapeColor()`에서 `Square`의 RGB 값을 바꾼다. 왼쪽 사각형 색과 빈 사각형 칸의 안내 색이 함께 바뀌는지 확인한다.

한 줄이 여러 함수에 영향을 주는지 확인하는 것이 이 실습의 핵심이다. 바꾼 뒤 빌드 오류가 났다면 함수 이름·자료형·열거형 이름을 먼저 확인하고, 화면만 이상하다면 그리기 순서와 꼭짓점·좌표 계산을 확인한다.
