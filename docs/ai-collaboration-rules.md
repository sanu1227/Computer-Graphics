# 2인 팀 AI 협업 개발 규칙

두 명의 개발자와 각자의 AI가 같은 게임을 만들 때 적용할 규칙 초안이다. 핵심은 **작업 전 맥락 확인, 담당 범위 분리, 변경 근거 기록, 검증 후 인계**다.

## 1. 사용할 문서

| 문서 | 역할 | 관리 원칙 |
| --- | --- | --- |
| AGENTS.md | AI가 따라야 할 공통 작업 규칙 | 두 사람이 합의해 변경 |
| 공식 기획서 | 게임의 목표·규모·규칙 | 정식 기획서 경로 하나를 지정 |
| docs/TEAM.md | 담당 영역·공통 약속·기획서 경로·실행 방법 | 정해진 통합 담당자가 관리 |
| docs/tasks/A-001.md 등 | 작업별 범위·진행·검증·인계 | 해당 작업 담당자만 작성 |

위 경로는 게임 저장소에 적용할 권장 구성이다. TEAM.md와 작업 기록은 아직 생성하지 않았다. 기존에 같은 역할의 문서가 있으면 재사용한다. 새 문서에 같은 내용을 반복 복사하지 않는다.

## 2. 작업 전에는 관련 MD와 실제 코드를 먼저 읽는다

새 작업을 시작할 때 다음을 확인한다.

1. 적용되는 AGENTS.md.
2. TEAM.md에 지정된 기획서의 관련 부분.
3. TEAM.md의 담당 영역과 공통 약속.
4. 자신의 작업 기록과 수정 범위가 겹치는 진행 중 작업의 기록.
5. 실제 대상 코드, 현재 브랜치, 수정·삭제된 파일 상태.

읽은 뒤에는 **이번 작업의 목표, 수정할 범위, 완료 기준**을 짧게 정리하고 진행한다. 이전 대화에서 기억한 내용만으로 수정하지 않는다.

매 대화마다 모든 문서를 다시 읽을 필요는 없다. 새 작업·브랜치 변경·인계 후에는 다시 확인하고, 진행 중에는 변경되었거나 불확실한 부분만 확인한다. 기획서가 없거나 삭제 상태라면 최신 경로를 확인하며, 과거 파일을 임의로 복원하지 않는다. 관련 없는 독립 작업은 계속할 수 있다.

## 3. 한 작업에는 담당자 한 명과 수정 범위를 정한다

- 시작 전에 작업 ID, 담당자, 브랜치, 수정할 파일·폴더, 완료 기준을 기록한다.
- 작업 ID는 A-001, B-001처럼 담당자별로 구분한다. 번호는 각 담당자가 관리한다.
- 같은 파일을 두 AI가 동시에 수정하지 않는다. 담당 범위가 겹치면 작업을 나누거나 순서를 정한다.
- 다른 담당의 코드를 읽고 분석하는 것은 가능하다. 수정은 배정된 범위 안에서 한다.
- 한 사람이 같은 작업 폴더에서 두 AI를 실행하는 경우에도 동일하게 적용한다. 병렬 작업은 별도 브랜치와 별도 작업 폴더 또는 worktree로 분리한다.

**MD는 작업 기록이며 파일 잠금 장치가 아니다.** 두 PC의 기록은 Git으로 공유되기 전까지 자동으로 같아지지 않는다. 담당 분배를 두 사람이 공유한 상태에서 시작해야 한다. 이미 담당이 확정된 작업에 매번 재승인을 요구하지 않는다.

## 4. 공통 약속은 임의로 바꾸지 않는다

두 사람 모두 사용하는 함수의 이름·인자, 좌표계, 파일 형식, 자원 경로, 시작 코드, 빌드 설정은 공통 영역으로 취급한다.

- 먼저 TEAM.md에 필요한 약속만 정한다. 긴 설계 문서를 미리 만들 필요는 없다.
- 변경이 필요하면 이유, 영향받는 코드, 필요한 상대 작업을 기록한다.
- 영향받는 담당과 조율한 뒤 한 사람이 해당 변경을 수행한다.
- 이미 합의된 인터페이스 내부의 구현·버그 수정은 담당자가 진행한다.
- 다른 담당에게 필요한 기능이 아직 없다면 요구사항을 남긴다. 같은 기능을 다른 이름으로 중복 구현하지 않는다.

예: 학교와 회사가 함께 사용하는 시점 정렬 함수는 공통 영역이다. 학교 담당이 이름이나 결과 형식을 바꾸면 회사 담당도 수정해야 하므로 먼저 조율한다.

## 5. 기획 변경과 구현 선택을 구분한다

- 퍼즐 규칙, 조작법, 스테이지 수, 플레이 목표를 AI가 임의로 바꾸지 않는다.
- 함수 분리, 내부 변수명, 작은 코드 정리처럼 담당 범위 안의 구현 선택은 AI가 진행한다.
- 요청하지 않은 기능 추가, 파일 이동, 전면 리팩터링, 일괄 포맷 변경은 함께 하지 않는다.
- 기획과 코드가 다르면 차이를 먼저 확인한다. 기획서는 의도이고 코드는 현재 구현 상태이므로, 한쪽을 무조건 정답으로 보고 다른 쪽을 덮어쓰지 않는다.
- 승인된 변경은 해당 문서에 반영한다. AI의 제안은 채택 전까지 제안으로 표시한다.

## 6. 기존 변경과 Git 기록을 보호한다

- 수정 전에 Git 상태를 확인하고 기존 작업과 자신의 작업을 구분한다.
- 상대방의 수정·삭제·주석·임시 작업을 임의로 되돌리지 않는다.
- 충돌이 나면 양쪽 의도를 확인한다. 한쪽 파일을 통째로 선택해 다른 작업을 지우지 않는다.
- 강제 푸시, 강제 초기화, 파일 일괄 삭제, 작업을 숨기는 임의 stash로 충돌을 회피하지 않는다.
- 작업 브랜치는 codex/A-001-school 같은 이름으로 나눈다. main 통합은 지정된 담당자가 순서대로 처리한다.
- 새 작업은 최신 공유 기준에서 시작한다. 로컬 수정이 있으면 무작정 pull하지 말고 보존 방법과 대상 브랜치를 먼저 확인한다.
- 커밋·푸시·병합은 사용자가 허용한 범위에서 수행한다. 현재 작업에서 이미 허용했다면 같은 동작을 다시 확인하지 않는다.
- 커밋에는 해당 작업 파일만 포함하고, 커밋 전 포함 파일과 변경 내용을 확인한다. 로컬 커밋·원격 푸시·main 통합은 각각 구분해 보고한다.

## 7. 검증한 만큼만 완료했다고 말한다

- 변경에 맞는 빌드·기존 테스트·실행 확인을 수행한다.
- 그래픽스 작업은 빌드 성공과 실제 화면·조작 확인을 구분한다.
- 확인하지 못한 것은 이유와 다음 확인 방법을 기록한다. 실행하지 않은 기능을 정상이라고 단정하지 않는다.
- 착시 퍼즐은 정답 시점뿐 아니라 잘못된 시점, 초기화, 방 전환도 확인한다.
- 문서만 수정했다면 내용·경로·인코딩 등 문서에 맞는 검증을 한다.

작업 완료 기준은 시작할 때 정한 기준으로 판단한다. 원격 공유와 통합 여부는 별도 상태로 남긴다.

## 8. 끝날 때 다음 사람이 이어받을 기록을 남긴다

작업을 끝내거나 중단할 때 자신의 작업 기록에 다음을 남긴다.

- 무엇을 바꾸었는지와 이유.
- 실제 수정 파일.
- 확인한 결과와 확인하지 못한 부분.
- 공통 약속 또는 다른 담당에게 미치는 영향.
- 다음 작업 한두 가지.
- 커밋·푸시·통합 여부. 진행하지 않았다면 미수행으로 기록.

중요한 AI 활용 사례에는 **AI 요청 요약 / 사람이 검토·수정한 내용 / 확인 결과**를 짧게 남긴다. 과제의 AI 활용 보고서에도 사용할 수 있다. 대화 전체나 긴 실행 로그를 붙여 넣을 필요는 없다.

## 9. 매 작업에 사용할 요청 예시

> AGENTS.md와 TEAM.md, 공식 기획서의 관련 부분, 겹치는 진행 중 작업 기록을 먼저 읽어줘. 이번 작업은 A-001이고 목표는 학교의 계단 실물화야. 담당 범위를 확인하고 필요한 부분만 수정해줘. 공통 약속이나 상대 담당 파일 변경이 필요하면 영향을 먼저 설명해줘. 작업 후 검증 결과와 인계 내용을 작업 기록에 남겨줘.

파일·작업 ID·목표는 실제 프로젝트에 맞춰 바꾼다. 예시 문장 자체가 새로운 구현 작업을 지시하는 것은 아니다.

## 10. 적용 방법

1. 실제 게임 저장소의 공식 기획서 경로, 담당 A/B, 통합 담당자를 정한다.
2. [AGENTS 템플릿](AGENTS.template.md)을 게임 저장소 루트의 AGENTS.md에 반영한다. 기존 파일이 있으면 기존 지침을 보존하며 합친다.
3. TEAM.md에 기획서 경로, 담당 영역, 공통 약속, 현재 빌드·실행 방법만 간단히 기록한다.
4. [작업 기록 양식](ai-work-record-template.md)을 작업마다 복사해 docs/tasks/담당자-번호.md로 사용한다.
5. 두 사람이 같은 규칙과 최신 기준을 공유한 뒤 각자의 AI에 작업을 맡긴다.

현재 문서들은 적용용 초안이다. 저장소 루트의 AGENTS.md는 이번에 생성하지 않았고, 기존 기획서 삭제 상태도 복원하지 않았다.

Codex는 AGENTS.md를 프로젝트 지침으로 읽는다. 일반 MD를 두는 것만으로 모두 자동으로 읽는 것은 아니므로, 읽을 문서를 AGENTS.md에서 지정한다. 다른 AI 도구에서도 시작 프롬프트로 같은 문서를 지정할 수 있다. [OpenAI 공식 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
