# 1-11 보드판 이동과 충돌 쉽게 읽는 코드 해설

이 문서는 [1-11.cpp](../1-4/1-4/1-11.cpp)가 어떻게 움직이는지 쉽게 설명한다. 먼저 게임의 흐름을 이해하고, 그다음 짧은 코드와 숫자 예시를 읽으면 된다. 전체 코드를 외우려고 하지 말고, **이 함수가 무엇을 맡는지**부터 확인한다.

현재 조작 방법은 다음과 같다.

| 입력 | 동작 |
| --- | --- |
| 방향키 또는 `WASD` | 해당 방향으로 한 칸 이동 |
| `Space` | 지그재그 순서의 다음 칸으로 이동 |
| `R` | 주인공과 장애물을 새로 배치 |
| `ESC` | 종료 |

창 크기는 `1000×900`이고, 기본 보드는 `20×20`이다. 실행할 때 보드 크기를 `5~30` 사이로 입력할 수 있다. 아무것도 쓰지 않고 Enter를 누르면 20을 사용한다.

**현재는 키를 눌러야 이동한다.** `Space` 한 번으로 끝까지 자동 이동하는 코드는 없다. 여러 번 누르거나 누르고 있으면 입력이 들어올 때마다 지그재그로 한 칸씩 이동한다.

# 1부 게임을 만드는 순서

## 1 먼저 전체 흐름을 알아본다

프로그램이 하는 일을 크게 나누면 네 가지다.

1. 보드 크기를 입력받는다.
2. 창을 만들고 주인공과 장애물을 준비한다.
3. 입력을 받고, 위치와 모양을 바꾸고, 다시 그린다.
4. 종료하면 사용한 자원을 정리한다.

이 흐름을 시작하는 함수가 [`main()`](../1-4/1-4/1-11.cpp#L517)이다. C++ 프로그램은 `main()`에서 실행을 시작한다. 함수가 파일의 위에 적혀 있다고 먼저 실행되는 것은 아니다.

함수는 **한 가지 일을 모아 놓은 코드**라고 생각하면 된다. `DrawPlayer()`는 주인공 그리기, `ResetGame()`은 게임 초기화를 맡는다. 다른 함수가 이름을 불러 주면 실행된다.

창이 열린 뒤에는 아래 세 줄을 계속 반복한다.

```cpp
DrawScene(deltaTime);
glfwSwapBuffers(g_window);
glfwPollEvents();
```

- `DrawScene()`: 지금 상태에 맞는 그림을 만든다.
- `glfwSwapBuffers()`: 완성된 그림을 화면에 보여 준다.
- `glfwPollEvents()`: 키 입력이나 창 크기 변경을 확인한다.

이 반복 한 번으로 만드는 화면을 **한 프레임**이라고 부른다. `deltaTime`은 이전 프레임 이후 지난 시간이다. 나중에 충돌 효과를 지울 때 사용한다.

**직접 확인:** 프로그램을 켜고 보드 크기를 입력한다. 창이 안 열리면 콘솔에서 입력을 기다리는지 먼저 본다.

## 2 창을 만들고 크기를 정한다

창의 처음 크기는 [파일 위쪽의 상수](../1-4/1-4/1-11.cpp#L16)로 정한다.

```cpp
constexpr int WINDOW_WIDTH = 1000;
constexpr int WINDOW_HEIGHT = 900;
```

`WIDTH`는 너비, `HEIGHT`는 높이다. `constexpr`는 프로그램이 실행되는 동안 바꾸지 않을 값을 뜻한다.

`main()`에서는 이 두 숫자로 창을 만든다.

```cpp
g_window = glfwCreateWindow(WINDOW_WIDTH, WINDOW_HEIGHT, "1-11 GLSL Board Movement", nullptr, nullptr);
```

`glfwCreateWindow()`는 창을 만드는 함수다. 앞의 두 값은 크기, 그다음 문자열은 창 제목이다.

창을 준비하는 순서는 다음과 같다.

1. `glfwInit()`: 창과 입력 기능을 사용할 준비를 한다.
2. `glfwWindowHint()`: OpenGL 3.3 Core Profile을 사용하도록 요청한다.
3. `glfwCreateWindow()`: 창을 만든다.
4. `glfwMakeContextCurrent()`: 이 창에 그림을 그리도록 연결한다.
5. `glewInit()`: OpenGL 그리기 함수들을 사용할 준비를 한다.

여기서 **창을 만든 뒤에 `glewInit()`을 호출한다**는 순서가 중요하다. 헤더도 `glew.h`를 `glfw3.h`보다 앞에 둔다.

창 크기 변경은 [`FramebufferSizeCallback()`](../1-4/1-4/1-11.cpp#L400)이 처리한다. 바뀐 너비와 높이를 `g_windowWidth`, `g_windowHeight`에 저장하고, `glViewport()`로 그리기 영역을 맞춘다. 보드는 이 저장된 크기를 보고 다시 계산한다.

**직접 확인:** 창을 늘리거나 줄여 본다. 칸과 도형도 함께 크기가 바뀌는지 본다.

## 3 보드 크기를 입력받는다

창 크기와 보드 크기는 다르다.

- `1000×900`: 창의 너비와 높이
- `20×20`: 가로 20칸, 세로 20칸

[`ReadBoardSize()`](../1-4/1-4/1-11.cpp#L488)가 입력을 받고 숫자를 돌려준다. `main()`은 그 숫자를 저장한다.

```cpp
g_boardSize = ReadBoardSize();
```

`g_boardSize`는 **보드 한 줄에 몇 칸이 있는지 저장하는 변수**다. 변수는 값을 담는 이름이라고 생각하면 된다.

현재 함수는 먼저 입력 한 줄을 문자열로 읽는다. 그다음 정수 하나가 들어 있는지 검사한다.

| 입력 예시 | 결과 |
| --- | --- |
| 빈 Enter | 20칸 사용 |
| `10` | 10칸 사용 |
| `5`, `30` | 허용 범위이므로 사용 |
| `4`, `31` | 범위 밖이라 다시 입력 |
| `abc`, `20.5`, `20 30` | 정수 하나가 아니라 다시 입력 |

`R`을 눌러도 보드 크기는 그대로다. 크기를 바꾸려면 프로그램을 다시 실행해 입력한다.

**직접 확인:** `abc`, `4`, `10` 순서로 입력한다. 앞의 두 입력은 거부되고 10칸 보드가 만들어져야 한다.

## 4 칸 위치를 행과 열로 저장한다

칸 위치를 기억할 때는 화면의 X·Y 대신 **행과 열**을 쓴다.

- `row`: 몇 번째 가로줄인지 나타낸다. 아래로 갈수록 커진다.
- `column`: 그 줄에서 몇 번째 칸인지 나타낸다. 오른쪽으로 갈수록 커진다.

둘 다 **0부터 센다.** 좌측 상단은 `(행 0, 열 0)`이다.

```text
             열 0     열 1     열 2     열 3     열 4
행 0        (0,0)    (0,1)    (0,2)    (0,3)    (0,4)
행 1        (1,0)    (1,1)    (1,2)    (1,3)    (1,4)
행 2        (2,0)    (2,1)    (2,2)    (2,3)    (2,4)
```

예를 들어 `(행 1, 열 2)`에서 오른쪽으로 가면 `(행 1, 열 3)`이다. 아래로 가면 `(행 2, 열 2)`다.

20칸 보드에서는 행과 열 모두 `0~19`만 가능하다. 20은 이미 보드 밖이다. 칸 개수는 20개지만 번호가 0부터 시작하기 때문이다.

**직접 확인:** 아래로 한 번 이동하면 행만 바뀌고, 오른쪽으로 한 번 이동하면 열만 바뀌는지 코드를 읽어 본다.

## 5 주인공과 장애물 정보를 묶는다

주인공의 정보는 [`Player`](../1-4/1-4/1-11.cpp#L55)에 모아 둔다.

```cpp
struct Player
{
    int row = 0;
    int column = 0;
    ShapeType shape = ShapeType::Square;
    Color color{ 1.0f, 0.85f, 0.15f };
};
```

`struct`는 관련된 값을 한 묶음으로 만드는 문법이다. 주인공에게는 위치, 모양, 색이 필요하므로 함께 묶었다.

| 이름 | 쉬운 뜻 | 처음 값 |
| --- | --- | --- |
| `row` | 주인공이 있는 행 | 0 |
| `column` | 주인공이 있는 열 | 0 |
| `shape` | 주인공 모양 | 사각형 |
| `color` | 주인공 색 | 노란빛 |

`ShapeType::Square`는 사각형을 뜻한다. `ShapeType::Triangle`은 삼각형, `ShapeType::InvertedTriangle`은 역삼각형이다.

색은 빨강·초록·파랑 세 숫자로 저장한다. 이것을 RGB라고 부른다. 각각 0에 가까울수록 약하고 1에 가까울수록 강하다. 예를 들어 `(1,0,0)`은 빨강, `(0,0,1)`은 파랑이다.

장애물은 [`Obstacle`](../1-4/1-4/1-11.cpp#L46)에 저장한다. 주인공과 비슷하지만 `sizeRatio`라는 크기 비율도 가진다. `0.6`이면 도형 크기를 칸 크기의 60%로 정한다.

주인공 한 개는 `g_player`, 장애물 여러 개는 `g_obstacles`에 저장한다. `std::vector`는 이런 여러 값을 담는 목록이다.

**직접 확인:** 충돌 후 삼각형이 되어도 `g_player`가 주인공이다. 사각형이라는 모양 자체가 주인공을 구별하는 기준은 아니다.

## 6 칸의 중심 위치를 계산한다

이제 행·열을 화면에 그릴 위치로 바꾼다. [`CellCenter()`](../1-4/1-4/1-11.cpp#L264)가 칸의 중심 X·Y를 구한다.

먼저 보드와 칸 크기를 계산한다.

```text
보드 한 변 = 화면의 짧은 쪽 - 48
칸 한 변 = 보드 한 변 ÷ 한 줄의 칸 수
```

화면 크기 변수의 값이 `1000×900`이면 짧은 쪽은 900이다. 보드 한 변은 `900-48=852`가 된다. 20칸 보드라면 한 칸은 `852÷20=42.6`이다.

48은 화면 가장자리에 남기는 여백이다. 보드는 화면 가운데에 놓는다.

```text
보드 왼쪽 위치 = (1000 - 852) ÷ 2 = 74
보드 위쪽 위치 = (900 - 852) ÷ 2 = 24
```

칸 중심은 칸의 시작 위치에서 반 칸 더 들어간 곳이다.

```cpp
return {
    BoardLeft() + (static_cast<float>(column) + 0.5f) * cellSize,
    BoardTop() + (static_cast<float>(row) + 0.5f) * cellSize
};
```

처음에는 문법보다 `+0.5f`에 집중한다. **칸의 모서리가 아니라 가운데에 그리기 위해 반 칸을 더한다.** 좌측 상단 칸 중심은 `(95.3,45.3)`이다.

`static_cast<float>`는 행·열의 정수를 실수로 바꾸는 표현이다. 소수점이 있는 크기와 함께 계산하기 위해 사용한다.

**직접 확인:** 보드 크기를 10으로 입력하면 전체 보드 크기는 같고, 칸은 20칸일 때보다 커진다.

## 7 도형은 꼭짓점으로 만든다

컴퓨터는 사각형이라는 이름만으로 그리지 않는다. **어느 위치에 점이 있고, 어떤 점끼리 이어지는지** 알려 줘야 한다. 도형의 모서리 점을 꼭짓점 또는 정점이라고 부른다.

[`AddQuad()`](../1-4/1-4/1-11.cpp#L203)는 사각형을 삼각형 두 개로 만든다.

```text
왼쪽 위 A ───── B 오른쪽 위
         │    /│
         │  /  │
         │/    │
왼쪽 아래 D ─── C 오른쪽 아래

첫 삼각형: A, B, C
둘째 삼각형: A, C, D
```

두 삼각형을 채우면 사각형이 된다. 실제 코드는 삼각형 하나마다 정점 세 개를 넣으므로 총 여섯 개를 사용한다.

[`AddTriangle()`](../1-4/1-4/1-11.cpp#L213)은 점 세 개를 만든다. 위쪽에 꼭대기를 놓으면 삼각형, 아래쪽에 꼭대기를 놓으면 역삼각형이다.

```cpp
const float halfSize = size * 0.5f;
```

이 줄은 도형 크기의 절반을 구한다. 중심에서 왼쪽으로 절반, 오른쪽으로 절반 떨어뜨려 양 끝을 정한다. Y도 같은 방식으로 정한다. 화면 좌표에서는 Y가 작을수록 위쪽이다.

[`AddShape()`](../1-4/1-4/1-11.cpp#L231)은 모양을 보고 알맞은 함수를 고른다.

- 사각형이면 `AddQuad()`
- 삼각형이나 역삼각형이면 `AddTriangle()`

현재 삼각형은 너비와 높이를 같은 크기로 정한 이등변삼각형이다. 정삼각형 전용 공식을 사용하는 것은 아니다.

**직접 확인:** `AddTriangle()`에서 꼭대기 점의 Y가 위쪽인지 아래쪽인지 찾아 본다.

## 8 장애물을 겹치지 않는 칸에 배치한다

[`CreateObstacles()`](../1-4/1-4/1-11.cpp#L283)는 다음 순서로 장애물을 만든다.

1. 이전 장애물 목록을 비운다.
2. 장애물을 놓을 수 있는 칸을 전부 모은다.
3. 칸 목록의 순서를 무작위로 섞는다.
4. 앞에서부터 필요한 개수만큼 사용한다.
5. 각 장애물의 모양·크기·색을 정한다.

시작 칸 `(0,0)`은 목록에 넣지 않는다. 주인공이 출발하는 곳이기 때문이다.

```cpp
if (row != 0 || column != 0)
    cells.emplace_back(row, column);
```

쉽게 읽으면 **행과 열이 둘 다 0인 칸만 빼고 넣는다**는 뜻이다. `emplace_back()`은 목록 뒤에 값을 추가한다.

```cpp
std::shuffle(cells.begin(), cells.end(), g_random);
```

`std::shuffle()`은 목록 순서를 섞는다. 같은 칸을 반복해서 뽑지 않고 서로 다른 칸을 섞어 사용하므로 장애물끼리 같은 칸에 놓이지 않는다.

개수는 전체 칸의 약 1/6이며 최소 12개다. 사용할 칸이 그보다 적다면 칸 수까지만 만든다.

| 보드 | 장애물 |
| --- | --- |
| `5×5` | 12개 |
| `10×10` | 16개 |
| `20×20` | 66개 |
| `30×30` | 150개 |

장애물 크기는 칸의 `45~78%`다. 칸 중심에 놓으므로 셀 안에 들어간다. 세 모양의 개수가 같도록 맞추는 코드는 없다.

**직접 확인:** `R`을 여러 번 누른다. 시작 칸은 비어 있고, 장애물 위치·모양·크기·색은 달라지는지 본다.

## 9 방향키를 한 칸 이동에 연결한다

[`KeyCallback()`](../1-4/1-4/1-11.cpp#L379)은 키가 눌리면 실행된다. 이렇게 입력이 발생할 때 호출되는 함수를 **콜백 함수**라고 부른다.

```cpp
else if (key == GLFW_KEY_RIGHT || key == GLFW_KEY_D)
    MovePlayerByCell(0, 1);
```

이 줄은 오른쪽 방향키 또는 D가 들어오면 오른쪽으로 한 칸 이동하라는 뜻이다.

`MovePlayerByCell()`의 숫자는 **행 변화, 열 변화 순서**다.

| 코드 | 뜻 |
| --- | --- |
| `MovePlayerByCell(0,1)` | 행 유지, 열 1 증가: 오른쪽 |
| `MovePlayerByCell(0,-1)` | 행 유지, 열 1 감소: 왼쪽 |
| `MovePlayerByCell(-1,0)` | 행 1 감소, 열 유지: 위쪽 |
| `MovePlayerByCell(1,0)` | 행 1 증가, 열 유지: 아래쪽 |

[`MovePlayerByCell()`](../1-4/1-4/1-11.cpp#L374)은 현재 위치에 이 변화량을 더한다.

```cpp
MovePlayerToCell(g_player.row + rowDelta, g_player.column + columnDelta);
```

예를 들어 현재 위치가 `(2,3)`이고 아래 키를 누르면 `(2+1,3+0)`, 즉 `(3,3)`으로 이동을 요청한다.

**직접 확인:** 0부터 시작하므로 위로 갈 때 행은 `-1`, 아래로 갈 때 행은 `+1`이라는 점을 확인한다.

## 10 움직이기 전에 두 가지를 확인한다

[`MovePlayerToCell()`](../1-4/1-4/1-11.cpp#L343)은 실제 위치를 바꾸는 함수다. 방향키와 Space 모두 마지막에는 이 함수를 사용한다.

먼저 목적지가 보드 안인지 확인한다.

```cpp
if (row < 0 || row >= g_boardSize || column < 0 || column >= g_boardSize)
    return false;
```

20칸 보드에서 `row=-1`이나 `column=20`이면 밖이다. `return false`는 이동 실패라고 알려 주면서 함수를 끝낸다.

그다음 이전 이동에서 충분한 시간이 지났는지 확인한다.

```cpp
const double currentTime = glfwGetTime();
if (currentTime - g_lastMoveTime < MOVE_INTERVAL)
    return false;
```

`glfwGetTime()`은 현재 시간을 구한다. 현재 시간에서 마지막 이동 시간을 빼면 두 이동 사이의 간격이 나온다. 간격이 `0.12초`보다 짧으면 이번 입력을 무시한다.

두 검사를 통과하면 다음 일을 한다.

1. 마지막 이동 시간을 기록한다.
2. 주인공의 행과 열을 바꾼다.
3. 지그재그 번호도 새 위치에 맞춘다.
4. 그 칸에 장애물이 있는지 확인한다.

빠른 입력을 저장해 나중에 이동하는 기능은 없다. 키를 눌렀는데 이동하지 않았다면 경계나 시간 제한에 걸렸을 수 있다.

**직접 확인:** 시작 칸에서 위나 왼쪽을 누르면 움직이지 않아야 한다. 천천히 누르면 이동하고, 아주 빠르게 누르면 일부 입력이 무시될 수 있다.

## 11 Space는 지그재그 순서를 따라간다

방향키는 원하는 방향으로 이동한다. Space는 **칸마다 붙인 지그재그 번호**를 하나 증가시킨다.

5칸 보드의 번호를 보면 쉽다.

```text
행 0:  0   1   2   3   4
행 1:  9   8   7   6   5
행 2: 10  11  12  13  14
행 3: 19  18  17  16  15
행 4: 20  21  22  23  24
```

0에서 시작해 1, 2, 3, 4로 오른쪽 이동한다. 다음 5는 4의 바로 아래다. 그다음은 6, 7, 8, 9로 왼쪽 이동한다. 다음 줄에서는 다시 오른쪽으로 간다.

[`MovePlayer()`](../1-4/1-4/1-11.cpp#L361)은 현재 번호에 1을 더하고, 그 번호가 어느 행·열인지 계산한다. 현재 번호는 `g_playerPathIndex`에 저장한다.

| 위치 | Space를 누른 결과 |
| --- | --- |
| 3번 칸 | 4번 칸으로 오른쪽 이동 |
| 4번 칸 | 5번 칸으로 아래 이동 |
| 5번 칸 | 6번 칸으로 왼쪽 이동 |
| 마지막 24번 칸 | 다음 칸이 없으므로 이동하지 않음 |

방향키로 다른 칸에 가면 지그재그 번호도 그 칸에 맞게 바뀐다. 그래서 이후 Space를 눌러도 현재 칸부터 이어진다.

20칸 보드의 마지막 번호는 `20×20-1=399`이고, 위치는 **맨 아래 행의 왼쪽 끝**이다. 행마다 방향을 바꾸므로 마지막 칸이 항상 오른쪽 아래인 것은 아니다.

**직접 확인:** 5칸 보드에서 Space를 반복해 누른다. 줄 끝에서 한 칸 내려가 반대 방향으로 움직이는지 본다. 마지막 칸에서도 방향키로 다른 칸에 갈 수 있다. 현재는 도착 후 조작을 잠그지 않는다.

## 12 충돌하면 모양을 교환하고 주인공 색만 바꾼다

현재 충돌 규칙은 단순하다. **주인공과 장애물이 같은 칸에 있으면 충돌이다.**

[`FindObstacle()`](../1-4/1-4/1-11.cpp#L273)은 장애물 목록에서 같은 행·열을 가진 장애물을 찾는다. 찾으면 [`ResolveCollision()`](../1-4/1-4/1-11.cpp#L331)이 다음 두 줄을 실행한다.

```cpp
std::swap(g_player.shape, obstacle->shape);
g_player.color = obstacle->color;
```

`std::swap()`은 두 모양을 **서로 교환**한다. 색은 `=`로 장애물의 색을 주인공에게 복사한다. 장애물 색은 바뀌지 않는다.

| 대상 | 충돌 전 | 충돌 후 |
| --- | --- | --- |
| 주인공 | 노란 사각형 | 파란 삼각형 |
| 장애물 | 파란 삼각형 | 파란 사각형 |

새 색을 랜덤으로 만드는 것이 아니다. 주인공이 장애물의 색을 가져오며, 장애물은 기존 색을 유지한다.

위치와 크기는 교환하지 않는다. 장애물은 충돌 칸에 남고, 주인공은 계속 움직일 수 있다. 주인공이 나갔다가 다시 들어오면 모양은 다시 교환하고 색은 그 장애물의 색으로 설정한다.

**직접 확인:** 충돌 후 옆 칸으로 이동해 본다. 남아 있는 장애물은 이전 주인공 모양으로 바뀌지만 색은 그대로인지 본다.

## 13 주인공은 장애물 위에 그린다

[`DrawScene()`](../1-4/1-4/1-11.cpp#L465)은 다음 순서로 장면을 만든다.

```cpp
DrawBoard();
DrawObstacles();
DrawPlayer();
DrawCollisionEffect();
```

현재는 같은 위치에 그리면 **나중에 그린 그림이 앞의 그림을 덮는다.** 따라서 위의 순서는 다음 뜻이다.

1. 보드가 바닥에 있다.
2. 장애물이 보드 위에 있다.
3. 주인공이 장애물 위에 있다.
4. 충돌 효과가 가장 위에 있다.

충돌하면 주인공과 장애물이 같은 칸 중심에 놓인다. 주인공이 위에 있으므로 장애물이 가려질 수 있다. 교환된 장애물을 보려면 주인공을 옆 칸으로 옮기면 된다. 크기나 모양이 다르면 장애물 일부는 주변에 보일 수 있다.

**직접 확인:** 충돌 칸에서 멈춘 화면과 옆 칸으로 이동한 화면을 비교한다.

## 14 충돌 테두리는 잠깐 남았다가 사라진다

충돌이 일어나면 효과를 표시할 시간을 저장한다.

```cpp
g_collisionTimer = COLLISION_EFFECT_TIME;
```

현재 `COLLISION_EFFECT_TIME`은 `0.70f`다. 즉 효과의 남은 시간을 0.70초로 설정한다.

매 프레임에서는 지난 시간만큼 뺀다.

```cpp
g_collisionTimer = std::max(0.0f, g_collisionTimer - deltaTime);
```

예를 들어 남은 시간이 0.70초이고 0.10초가 지났다면 0.60초가 된다. `std::max(0.0f,...)`는 결과가 음수가 되지 않게 한다.

[`DrawCollisionEffect()`](../1-4/1-4/1-11.cpp#L443)은 남은 시간이 0이면 아무것도 그리지 않는다. 시간이 남으면 충돌 칸에 사각형 테두리를 그린다. 시간이 줄어들수록 테두리가 조금 커지고, 색은 노란빛에서 주황빛으로 바뀐다.

효과 위치는 충돌한 행·열을 따로 저장한다. 주인공이 움직여도 효과는 **충돌했던 칸**에 남는다. 다시 다른 칸과 충돌하면 효과 위치와 시간을 새 충돌로 바꾼다. 여러 충돌 효과를 동시에 저장하지는 않는다.

**직접 확인:** 충돌 직후 옆으로 이동한다. 주인공은 움직이고 이전 충돌 칸의 테두리는 잠시 남아야 한다.

## 15 R을 누르면 처음 상태로 돌린다

[`ResetGame()`](../1-4/1-4/1-11.cpp#L320)은 새 게임을 준비한다.

```cpp
g_player = Player{};
g_playerPathIndex = 0;
g_lastMoveTime = -MOVE_INTERVAL;
g_collisionTimer = 0.0f;
g_collisionRow = -1;
g_collisionColumn = -1;
CreateObstacles();
```

한 줄씩 쉽게 읽으면 다음과 같다.

| 코드 | 뜻 |
| --- | --- |
| `g_player = Player{}` | 주인공을 처음의 노란 사각형으로 되돌린다. 위치도 `(0,0)`이다. |
| `g_playerPathIndex = 0` | 지그재그 경로를 첫 칸으로 되돌린다. |
| `g_lastMoveTime = -MOVE_INTERVAL` | 시작 직후에도 이동할 수 있도록 이전 시간을 설정한다. |
| `g_collisionTimer = 0.0f` | 충돌 효과를 끈다. |
| 효과 행·열의 `-1` | 저장된 충돌 칸이 없다고 표시한다. |
| `CreateObstacles()` | 장애물을 새로 만든다. |

`Player{}`는 구조체에 적힌 기본값으로 주인공 정보를 만든다. `R`은 보드 크기나 창 크기를 다시 묻지 않는다.

**직접 확인:** 충돌로 모양과 색이 바뀐 뒤 R을 누른다. 주인공이 시작 칸의 노란 사각형으로 돌아와야 한다.

# 2부 짧은 코드로 더 이해하기

여기부터는 1부에서 설명한 코드를 조금 더 자세히 읽는다. 전체 문법을 한 번에 외우지 않아도 된다. 필요할 때 해당 항목을 찾아본다.

아래 코드는 설명에 필요한 부분만 발췌한 것이다. 일부 실습용 코드는 원본의 긴 식을 나누어 썼다. 각 블록만 복사하면 전체 프로그램이 완성되는 것은 아니다.

## 16 자주 나오는 기호를 쉬운 말로 읽는다

| 표현 | 쉬운 뜻 | 예시 |
| --- | --- | --- |
| `=` | 오른쪽 값을 왼쪽에 저장 | `row = 3`이면 행에 3 저장 |
| `==` | 두 값이 같은지 확인 | `row == 0`이면 첫 행인지 확인 |
| `!=` | 두 값이 다른지 확인 | `row != 0`이면 첫 행이 아닌지 확인 |
| `<`, `>` | 작은지, 큰지 확인 | `row < 0`이면 보드 위쪽 밖인지 확인 |
| `>=`, `<=` | 같은 경우도 포함해 비교 | `row >= 20`이면 20도 포함 |
| `||` | 또는 | 오른쪽 방향키 또는 D |
| `&&` | 그리고 | 최소값 이상이고 최대값 이하 |
| `!` | 결과 반대로 | 입력 성공을 입력 실패로 바꾸어 검사 |
| `%` | 나눈 뒤 남은 값 | `7 % 5`는 2 |
| `return` | 함수를 끝내고 결과를 돌려줌 | `return false`는 실패 결과 반환 |
| `continue` | 현재 반복을 끝내고 다음 반복으로 | 잘못된 입력이면 다시 입력받기 |

조건문은 다음처럼 읽으면 된다.

```cpp
if (row < 0)
    return false;
```

**행이 0보다 작으면 이동 실패로 끝낸다.** 기호 이름보다 문장으로 읽는 연습이 중요하다.

`GLFW_KEY_RIGHT`는 GLFW에서 정한 오른쪽 방향키 이름이다. `GLFW_PRESS`는 키를 누르는 순간, `GLFW_REPEAT`는 누른 채 반복 입력, `GLFW_RELEASE`는 키를 떼는 순간이다. 현재 코드는 앞의 두 경우를 받는다.

## 17 목록을 다루는 코드를 읽는다

장애물을 만드는 코드는 `cells`라는 칸 목록과 `g_obstacles`라는 장애물 목록을 사용한다.

```cpp
g_obstacles.clear();
```

`clear()`는 목록 안의 내용을 비운다. 재시작할 때 이전 장애물이 남지 않게 한다.

```cpp
cells.emplace_back(row, column);
```

`emplace_back()`은 행·열 한 쌍을 목록 뒤에 추가한다.

```cpp
g_obstacles.push_back(obstacle);
```

`push_back()`은 만든 장애물 한 개를 목록 뒤에 넣는다.

```cpp
for (Obstacle& obstacle : g_obstacles)
```

이 반복문은 장애물 목록의 원소를 하나씩 꺼내서 살펴본다. `&`는 원래 목록에 있는 장애물을 직접 사용한다는 뜻이다. 충돌로 바뀐 값도 그 목록에 남아야 하므로 중요하다.

**생각해 보기:** `CreateObstacles()`의 `clear()`를 없애고 R을 여러 번 누르면 어떻게 될까? 이전 장애물이 남은 채 새 장애물이 계속 추가된다.

## 18 왜 같은 칸이 여러 번 뽑히지 않을까

장애물을 놓을 때마다 행·열을 무작위로 새로 뽑으면 같은 칸이 두 번 나올 수 있다. 현재는 칸 목록을 먼저 만든 뒤 **순서만 섞어서** 사용한다.

다섯 칸의 예시를 생각해 보자.

```text
섞기 전: A, B, C, D, E
섞은 뒤: D, A, E, B, C
앞의 세 칸 사용: D, A, E
```

순서를 바꿔도 같은 칸이 추가되는 것은 아니다. 따라서 D, A, E는 서로 다른 칸이다. 실제 코드는 시작 칸을 뺀 모든 칸을 이렇게 섞는다.

장애물 수를 구하는 두 줄도 나누어 읽는다.

```cpp
const int requestedCount = std::max(12, (g_boardSize * g_boardSize) / 6);
const int obstacleCount = std::min(requestedCount, static_cast<int>(cells.size()));
```

- `std::max()`: 두 숫자 중 큰 것을 선택한다. 최소 12개를 요청한다.
- `std::min()`: 두 숫자 중 작은 것을 선택한다. 준비한 칸 수를 넘지 않게 한다.

20칸 보드에서는 `400÷6`을 정수로 계산해 66개가 된다. 소수 부분은 버린다.

## 19 지그재그 번호 계산을 작은 숫자로 풀어 본다

여기서는 5칸 보드의 **7번 칸**을 찾는다고 가정한다.

[`MovePlayer()`](../1-4/1-4/1-11.cpp#L361)은 먼저 행을 계산한다.

```cpp
const int row = nextPathIndex / g_boardSize;
```

7을 5로 나누면 정수 계산에서 1이다. 따라서 행은 1이다.

그다음 그 줄 안에서 몇 번째로 이동했는지 구한다.

```cpp
const int offset = nextPathIndex % g_boardSize;
```

`7 % 5`는 2다. 행 1에서 순서상 세 번째 칸이다.

마지막으로 열을 계산한다.

```cpp
const int column = (row % 2 == 0) ? offset : g_boardSize - 1 - offset;
```

이 긴 줄은 다음 뜻이다.

- 행이 짝수면 열을 `offset`으로 한다.
- 행이 홀수면 열을 `보드 크기-1-offset`으로 한다.

행 1은 홀수이므로 열은 `5-1-2=2`다. 따라서 7번 칸의 위치는 `(행 1, 열 2)`다.

`조건 ? A : B`는 **조건이 맞으면 A, 아니면 B**라는 문법이다. 처음에는 위의 두 문장으로 나누어 읽어도 된다.

반대로 현재 칸에서 지그재그 번호를 구할 때는 다음 식을 사용한다.

```cpp
g_playerPathIndex = row * g_boardSize +
    ((row % 2 == 0) ? column : g_boardSize - 1 - column);
```

행 1, 열 2를 넣으면 `1×5+(5-1-2)=7`이다. 방향키로 이동한 뒤에도 Space가 올바른 칸에서 이어지도록 번호를 맞추는 것이다.

**직접 확인:** 5칸 보드에서 행 1, 열 0의 번호를 구해 본다. 답은 `1×5+(4-0)=9`다.

## 20 충돌에서 화살표 기호는 무엇일까

충돌 코드에는 `obstacle->shape`라는 표현이 나온다.

```cpp
if (Obstacle* obstacle = FindObstacle(g_player.row, g_player.column))
```

쉽게 읽으면 **지금 주인공 칸에 장애물이 있는지 찾고, 찾은 장애물을 `obstacle`이라는 이름으로 사용한다**는 뜻이다. 못 찾으면 안쪽 코드를 실행하지 않는다.

`Obstacle*`는 장애물의 위치를 기억하는 포인터다. 여기서 위치는 화면 좌표가 아니라 **컴퓨터 메모리에서 해당 데이터가 저장된 주소**를 뜻한다.

- `g_player.shape`: 주인공의 모양
- `obstacle->shape`: 포인터로 찾은 장애물의 모양

`.`과 `->`는 모두 안에 있는 값을 꺼내는 표현이다. 직접 가진 객체는 `.`, 포인터로 찾아간 객체는 `->`를 쓴다고 이해하면 된다.

```cpp
std::swap(g_player.shape, obstacle->shape);
```

이 줄은 실제 장애물과 주인공의 모양을 교환한다. 단순히 주인공 모양에 장애물 모양을 복사하는 것과 다르다. 복사만 하면 장애물은 그대로 남지만, 교환하면 장애물도 이전 주인공 모양을 받는다.

## 21 셰이더는 위치와 색으로 화면을 만든다

C++은 주인공이 어디에 있고 어떤 모양인지 결정한다. 셰이더는 받은 정점의 위치와 색으로 화면을 만든다. **셰이더가 이동 키나 충돌 규칙을 판단하는 것은 아니다.**

현재 사용하는 파일은 두 개다.

| 파일 | 맡은 일 |
| --- | --- |
| [vertex.glsl](../1-4/1-4/vertex.glsl) | 정점의 위치를 OpenGL 좌표로 바꿈 |
| [fragment.glsl](../1-4/1-4/fragment.glsl) | 화면에 표시할 색을 정함 |

C++의 [`Vertex`](../1-4/1-4/1-11.cpp#L23)는 정점 하나에 필요한 값을 담는다.

```cpp
struct Vertex
{
    float x;
    float y;
    float red;
    float green;
    float blue;
};
```

앞의 두 숫자는 위치, 뒤의 세 숫자는 RGB 색이다.

VAO와 VBO는 처음에는 다음 정도로 구분하면 된다.

- **VBO**: 정점 숫자들을 저장하는 GPU 쪽 공간
- **VAO**: 그 숫자 중 어디가 위치이고 어디가 색인지 기록하는 설정

C++은 위치를 속성 번호 0에, 색을 속성 번호 1에 연결한다. 버텍스 셰이더도 같은 번호로 받는다.

```glsl
layout (location = 0) in vec2 position;
layout (location = 1) in vec3 color;
```

`vec2`는 숫자 두 개, `vec3`는 숫자 세 개다. 그래서 위치 X·Y는 `vec2`, RGB 색은 `vec3`로 받는다.

[`CreateShaderProgram()`](../1-4/1-4/1-11.cpp#L161)은 두 파일을 읽고 사용할 수 있게 준비한다. 파일이 없거나 GLSL 문법이 틀리면 오류 로그를 출력한다. 처음에는 위치와 색의 연결만 이해하고, 컴파일·링크 함수의 세부 인수는 원본을 보면서 읽어도 된다.

## 22 왜 좌표를 바꾸고 Y를 뒤집을까

C++에서는 화면 왼쪽 위를 `(0,0)`으로 생각한다. 오른쪽으로 가면 X가 커지고 아래로 가면 Y가 커진다.

OpenGL은 화면 표시용 좌표를 보통 `-1~1` 범위로 받는다. 위쪽은 Y가 양수다. 따라서 버텍스 셰이더가 두 좌표 체계를 맞춘다.

```glsl
vec2 normalizedPosition = position / windowSize * 2.0 - 1.0;
normalizedPosition.y = -normalizedPosition.y;
```

첫 줄은 화면 크기에 맞춰 위치를 `-1~1`로 바꾼다. 두 번째 줄은 위아래 방향을 맞춘다.

화면이 `1000×900`일 때 다음처럼 변한다.

| 화면 위치 | OpenGL 위치 |
| --- | --- |
| 왼쪽 위 `(0,0)` | `(-1,1)` |
| 가운데 `(500,450)` | `(0,0)` |
| 오른쪽 아래 `(1000,900)` | `(1,-1)` |

`windowSize`는 C++에서 보내는 화면 너비·높이다. 이런 값을 셰이더에 전달할 때 `uniform`을 사용한다.

프래그먼트 셰이더는 받은 RGB 색을 출력한다.

```glsl
finalColor = vec4(vertexColor, 1.0);
```

`vec4`는 숫자 네 개다. RGB 뒤의 `1.0`은 알파값이며 현재는 불투명한 색을 나타낸다.

## 23 정점 목록은 언제 실제 그림이 될까

`AddVertex()`, `AddQuad()`, `AddTriangle()`은 이름을 부르는 순간 바로 화면에 그림을 그리지 않는다. 먼저 **이번 화면에 쓸 정점 목록**을 만든다.

[`DrawScene()`](../1-4/1-4/1-11.cpp#L465)은 다음 순서로 처리한다.

1. `g_vertices.clear()`: 지난 프레임의 정점 목록을 비운다.
2. 보드·장애물·주인공·효과의 정점을 차례대로 넣는다.
3. `glClear()`: 지난 화면을 지운다.
4. `glUseProgram()`: 사용할 셰이더를 선택한다.
5. `glUniform2f()`: 셰이더에 화면 크기를 보낸다.
6. `glBufferData()`: 정점 목록을 GPU에 보낸다.
7. `glDrawArrays()`: 보낸 정점으로 그림을 그린다.

`GL_TRIANGLES`는 정점 세 개씩 삼각형 하나로 그리라는 뜻이다. 그래서 사각형도 삼각형 두 개로 나눠서 정점을 만들었다.

데이터를 보낼 때와 그릴 때 쓰는 크기는 구분한다.

| 함수 | 필요한 숫자 |
| --- | --- |
| `glBufferData()` | 데이터 전체의 바이트 크기 |
| `glDrawArrays()` | 사용할 정점 개수 |

이제 처음의 세 줄을 다시 보면 전체 흐름이 연결된다. `DrawScene()`이 상태에 맞는 그림을 만들고, 화면을 보여 주고, 다음 입력을 받는 일을 계속 반복하는 것이다.

## 26 실제 창에서 순서대로 점검한다

다음 항목은 **직접 해 볼 점검 목록**이다. 빌드가 성공했다고 모든 화면 동작을 확인한 것은 아니다.

1. 보드 크기에 5를 입력하고 5×5 보드인지 본다.
2. 시작 칸에 주인공만 있고 장애물은 없는지 본다.
3. 네 방향키로 한 칸씩 움직인다.
4. 가장자리에서 보드 밖으로 나가지 않는지 본다.
5. Space를 반복해 줄 끝에서 내려가고 방향이 바뀌는지 본다.
6. 장애물에 들어가 모양이 교환되고 주인공 색이 장애물 색으로 바뀌는지 본다.
7. 옆으로 이동해 남은 장애물은 모양만 바뀌고 색은 유지되는지 본다.
8. 충돌 테두리가 잠시 남았다가 사라지는지 본다.
9. R을 눌러 처음 상태로 돌아오는지 본다.
10. ESC를 눌러 종료한다.

[1-4.vcxproj](../1-4/1-4/1-4.vcxproj)에서는 `1-11.cpp`를 빌드한다. 실행 파일 이름은 `1-11.exe`가 아니라 프로젝트 이름인 `1-4.exe`다. 현재 `Debug|x64`에서는 `1-10.cpp`가 제외되어 있다. 다른 빌드 구성을 사용할 때도 두 파일의 `main()`이 동시에 들어가지 않도록 확인한다.

`CreateObstacles()` 끝의 `assert`는 개발 중 상태가 맞는지 확인하는 코드다. 장애물 위치와 크기 등을 검사한다. 키 입력과 충돌 전체를 자동으로 테스트하는 것은 아니다. Release에서는 보통 이 검사가 빠지므로 게임 동작을 `assert` 안에 넣지 않는다.

## 27 더 자세히 볼 때 알아둘 점

먼저 위의 게임 흐름을 이해한 뒤 이 부분을 읽어도 된다.

- **같은 칸에 들어가면 충돌한다.** 장애물을 작게 그려도 그 칸에 들어갔을 때 교환된다. 꼭짓점끼리 닿는지 계산하는 코드는 아니다.
- **효과는 한 개만 기억한다.** 새 충돌이 생기면 이전 효과 위치와 시간을 새 것으로 바꾼다.
- **모양은 교환하고 주인공 색만 바꾼다.** 장애물의 색, 크기와 위치는 유지된다. 주인공 크기는 항상 칸의 66%다.
- **키 반복 속도는 운영체제의 영향을 받는다.** 현재는 `GLFW_REPEAT` 입력을 받는다. 자동 이동용 타이머가 따로 있는 것은 아니다. R도 길게 누르면 반복 재시작될 수 있다.
- **마지막 칸에서 조작을 잠그지 않는다.** Space로 더 진행할 수는 없지만 방향키로 다른 칸에 갈 수 있다.
- **프레임이 많이 느려지면 효과가 더 오래 남을 수 있다.** 타이머에서 빼는 `deltaTime`을 한 프레임에 최대 0.1초로 제한하기 때문이다.
- **창을 너무 작게 줄이면 보드 계산이 이상해질 수 있다.** 보드 크기는 짧은 쪽에서 48을 빼므로 48 이하의 창에서는 추가 처리가 필요하다.
- **초기 화면 배율 확인은 별도로 필요하다.** 현재 크기 변수는 1000×900으로 시작하고 이후 프레임버퍼 크기 콜백이 갱신한다. 시작 시 실제 프레임버퍼 크기를 조회하는 코드는 없다.

처음에는 **위치 변경, 충돌 교환, 다시 그리기**의 세 과정을 구분해서 읽는다. 위치가 바뀌는 곳은 `MovePlayerToCell()`, 모양과 색이 바뀌는 곳은 `ResolveCollision()`, 결과를 화면에 보여 주는 곳은 `DrawScene()`이다.
