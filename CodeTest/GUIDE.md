# OpenGL 시험용 기능 조합 안내

이 자료는 OpenGL 실습 1~23의 구현 패턴을 기능별로 다시 구성한 복붙용 참고서입니다. 원래 과제의 모든 조건을 그대로 재현한 답안은 아닙니다. 문제의 좌표, 도형 수, 키, 속도, 충돌 후 행동을 바꿔서 사용합니다.

코드에서 `[수정]`을 검색하면 설정값과 변경 결과를 찾을 수 있습니다. 각 기능은 설정값·상태·입력·갱신·그리기를 주석으로 구분합니다. 같은 물체에 기능을 합치는 방법은 [조합 설명](COMBINE.md)을 참고합니다.

## 가장 빠른 사용법

1. `index.html`을 더블클릭해서 브라우저로 엽니다. 인터넷 연결은 필요하지 않습니다.
2. 문제의 핵심 기능을 검색합니다. 예: `드래그`, `공전`, `관절`, `점프`, `카메라`.
3. **전체 실행 코드**를 복사해서 OpenGL 설정이 된 프로젝트의 `.cpp` 하나에 붙입니다.
4. 원래 프로젝트의 다른 `main()`이 있는 `.cpp`는 빌드에서 제외합니다.
5. 먼저 실행한 뒤 해당 기능의 이름공간 안에서 문제 조건을 수정합니다.
6. 추가 기능은 **기능 블록**과 **호출 등록부**를 참고해 합칩니다.

복사 버튼이 제한되면 코드 칸을 클릭하고 `Ctrl+A`, `Ctrl+C`로 복사합니다. `.cpp 파일` 링크 또는 `examples` 폴더의 파일을 에디터로 열어도 됩니다.

휴대폰의 ChatGPT·파일 앱 미리보기에서 검색이나 목록이 작동하지 않으면 `offline.html`을 엽니다. 이 열람판은 JavaScript 없이 모든 목차와 전체 코드를 표시합니다. 목차 또는 브라우저의 **페이지에서 찾기**를 사용하고, 코드는 직접 선택해 복사합니다. ZIP은 먼저 압축을 풉니다. 실제 휴대폰 미리보기 앱별 표시 지원은 다를 수 있습니다.

## 시험 환경 설정

- x64, C++17 이상을 사용합니다. `std::clamp` 때문에 C++17이 필요합니다.
- 포함 경로는 기존 실습과 같은 `GL/glew.h`, `GL/glfw3.h`, `GL/glm/glm.hpp` 형식입니다.
- 링크 라이브러리는 `opengl32.lib; glew32.lib; glfw3.lib`입니다.
- 동적 라이브러리를 쓰면 실행 시 해당 DLL을 찾을 수 있어야 합니다.
- 새 빈 콘솔 프로젝트에서는 미리 컴파일된 헤더를 사용하지 않도록 설정합니다.
- `F5` 키는 예제 창에서 초기화, `Esc`는 종료입니다. Visual Studio의 실행 단축키와 혼동하지 않습니다.
- 각 기능의 조작키는 원래 실습과 다를 수 있습니다. 색인의 키 설명을 확인합니다.

검사 스크립트는 설치된 Visual Studio와 사용자 속성 시트를 사용하며 기본 도구 집합은 `v145`입니다. 다른 PC에서는 설치된 도구 집합과 라이브러리 경로에 맞춰 설정합니다.

## 기능 두 개를 합치는 정확한 위치

예를 들어 **탱크가 움직이고 카메라도 움직이는 문제**라면 14번 전체 코드로 시작합니다.

1. 15번의 **기능 블록**에서 `namespace Camera { ... }` 전체를 복사합니다.
2. 14번 코드의 `// FEATURE_BLOCK_END` 바로 앞에 붙입니다.
3. 기존 등록부를 다음처럼 바꿉니다. `OnKey` 함수를 두 개 만들지 말고 그 안의 호출을 합칩니다.

```cpp
void OnReset() {
    JointModel::Reset();
    Camera::Reset();
}
void OnKey(int key, int action, int mods) {
    JointModel::Key(key, action, mods);
    Camera::Key(key, action, mods);
}
void OnMouse(int button, int action) {}
void OnCursor() {}
void OnUpdate(float dt) {}
void OnDraw() {
    JointModel::Draw(); // Camera::Draw는 카메라 예제의 배경 물체이므로 제외한다.
}
void OnCheck() {
    JointModel::Check();
    Camera::Check();
}
```

이 상태에서는 `Y`가 탱크 몸체와 카메라 자전에 동시에 전달됩니다. 한 기능의 키를 바꿔야 합니다. 준비된 23번 조합 예제는 카메라에 `Ctrl`을 함께 누를 때만 키를 전달하도록 구분합니다.

기능 조합은 전역 변수 이름만 피하면 끝나는 작업이 아닙니다. 다음 네 항목을 확인합니다.

| 충돌 항목 | 해결 방법 |
|---|---|
| 같은 키를 두 기능이 사용 | 키 변경 또는 Ctrl 같은 수정키로 한쪽에만 전달 |
| 두 Reset이 카메라나 `use2D` 설정 | 최종 설정을 한곳에서 결정 |
| 두 Draw가 바닥과 예제 물체를 중복 출력 | 필요한 Draw만 등록하거나 보조 Draw에서 그 부분 제거 |
| 두 기능이 같은 객체를 서로 다른 변수로 저장 | 기준 객체를 하나 정하고 다른 기능이 그 위치를 읽도록 수정 |

## 문제를 읽고 코드로 나누는 순서

예시 조건: “상자 5개가 ㄱ자 경로로 이동한다. 키로 정지한다. 카메라가 장면 주위를 회전한다.”

1. 객체 배열과 경로는 **16번 컨베이어**에서 가져옵니다.
2. 정지 토글은 `Conveyor::Key`, 이동은 `Conveyor::Update`에 이미 있습니다.
3. 카메라 공전은 **15번 Camera**의 `O` 분기를 가져옵니다.
4. `First`, `Second`, 객체 수, 속도, 키를 문제에 맞게 바꿉니다.
5. 경로 꺾임, 끝에서 재시작, 정지 후 재개를 각각 확인합니다.

예시 조건: “물체를 클릭해서 드래그한다. 목표 위치 근처에서 놓으면 붙는다.”

**07번 스냅**에 선택, 드래그, 오프셋 보존이 포함되어 있습니다. 한 물체라면 03번을 추가할 필요가 없습니다. 여러 물체라면 03번의 배열과 선택 인덱스를 사용하고, 마우스를 놓는 분기에 07번의 거리 검사를 적용합니다. 두 기능의 Draw를 그대로 함께 등록하면 서로 다른 두 물체가 생깁니다.

## 공통 바탕에서 가져다 쓰는 함수

| 함수 | 의미와 좌표 |
|---|---|
| `T({x,y,z})` | 이동 행렬 |
| `R(angle,{x,y,z})` | 도 단위 회전. 축은 길이가 0이면 안 됨 |
| `S({sx,sy,sz})` | 크기 행렬 |
| `Box(model,color)` | 원점 중심, 한 변 길이 1의 육면체 |
| `Sphere(model,color)` | 원점 중심, 반지름 1의 구 |
| `Rect(center,size,color,filled)` | 중심과 **전체** 너비·높이로 사각형 출력 |
| `Circle(center,radius,color,filled)` | 중심과 반지름으로 원 출력 |
| `Primitive(mode,points,model,color)` | 임의 정점 목록으로 점, 선, 삼각형 등 출력 |
| `HitRect(x,y,center,size)` | 점이 사각형 안에 있는지 검사 |
| `OverlapRect(a,sizeA,b,sizeB)` | 두 축 정렬 사각형의 겹침 검사. 회전 사각형의 정밀 충돌은 아님 |
| `SetView(...)` | 뷰포트, 카메라, 원근 또는 직교 투영 설정 |

`Rect`, `Circle`, `HitRect`의 2D 좌표는 **800×600 논리 화면**입니다. 창 크기가 바뀌어도 좌표 범위는 같습니다. 마우스는 `UpdateMouse()`에서 이 범위로 변환됩니다. 가로세로 비율을 다르게 늘리면 도형도 화면 비율에 따라 늘어납니다.

3D는 Y가 위로 증가합니다. `Box(T({0,0.5f,0}), Yellow)`는 바닥 높이 0 위에 높이 1인 상자를 놓습니다. `Sphere`는 기본 지름이 2이므로 지름 1을 원하면 `S({.5f,.5f,.5f})`를 적용합니다.

공통 그리기 함수는 이해와 복붙 편의를 위해 정점을 그릴 때마다 업로드합니다. 수십 개 도형 실습용입니다. 수천 개 이상 반복 출력하는 문제라면 정적 VBO나 인스턴싱 구조가 필요합니다.

## 변환 문제에서 바로 고르는 공식

| 문제 표현 | 코드 형태 | 주의점 |
|---|---|---|
| 자기 위치에서 회전 | `T(position) * R(angle,axis) * S(size)` | 크기, 회전, 이동 순으로 정점에 적용 |
| 원점을 중심으로 공전 | `R(angle,axis) * T(offset) * S(size)` | 회전이 위치에도 적용 |
| 특정 중심 주위 공전 | `T(center) * R(angle,axis) * T(offset) * S(size)` | offset은 중심에서 물체까지의 상대 위치 |
| 기존 정점의 경첩 회전 | `T(pivot) * R(angle,axis) * T(-pivot)` | pivot은 기존 정점과 같은 좌표계 |
| 관절에서 뻗은 부품 | `parent * T(joint) * R(angle,axis) * T(centerOffset) * S(size)` | 부모의 크기를 상속할지 먼저 결정 |
| 행성 위성 | `planetFrame * R(moonAngle,axis) * T(moonOffset) * S(moonSize)` | planetFrame에서 행성 자전·크기 제외 가능 |
| 정점 위치 최종 변환 | `projection * view * model * position` | 실제 적용은 오른쪽부터 |

`R()`은 **도**를 받지만 `std::sin`, `std::cos`, `std::atan2`는 **라디안**을 씁니다. 혼동하면 속도와 궤도가 크게 달라집니다.

## 가장 많이 바꾸는 조건

### 클릭 한 번과 누르고 있는 동안

토글은 `action == GLFW_PRESS`에서만 처리합니다. 한 칸씩 이동은 `GLFW_PRESS`와 `GLFW_REPEAT`를 받을 수 있습니다. 부드러운 연속 이동은 키 콜백에서 이동 여부를 저장하고 `Update(dt)`에서 `position += direction * speed * dt`를 수행합니다.

### 왕복과 한 번만 이동

왕복은 경계에서 속도 부호를 바꿉니다. 한 번만 이동은 진행률을 `std::min(1.0f, progress + dt / duration)`으로 제한하고 1에서 실행 상태를 꺼 줍니다. `duration`은 0보다 커야 합니다.

### 멈춤과 초기화

멈춤은 `running=false`만 바꿉니다. 초기화는 위치, 각도, 속도, 타이머, 선택 인덱스, 실행 플래그를 모두 복원합니다. 시작과 리셋에서 같은 `Reset()`을 호출하면 누락을 줄일 수 있습니다.

### 이동 방향 바라보기

2D에서 기본 앞쪽이 +X인 도형은 `atan2(dy,dx)`를 사용합니다. 3D에서 기본 앞쪽이 +Z인 로봇은 `atan2(dx,dz)`를 Y축 각도로 사용합니다. 방향 벡터 길이가 0이면 이전 각도를 유지합니다.

### 충돌 후 행동

같은 충돌 검사라도 문제에 따라 결과가 달라집니다. 정지는 다음 위치 반영 취소, 반사는 속도 부호 변경, 삭제는 `visible=false`, 모양 교환은 두 객체의 모양 값을 교환합니다. 물체 중심만 제한하지 말고 반크기 또는 반지름을 경계에서 빼야 합니다.

### 여러 카메라

상태는 한 번 갱신하고 같은 모델을 여러 번 그립니다. 위에서 내려다보는 카메라는 시선과 평행한 `(0,1,0)`을 up으로 주지 않습니다. 준비된 18번은 `(0,0,-1)`을 사용합니다. 각 뷰포트마다 지우려면 `glScissor`와 `GL_SCISSOR_TEST`를 같이 사용해야 합니다.

## 시험 직전 확인

- 선택한 예제 하나만 빌드되는지 확인합니다.
- `namespace` 블록은 `main()`과 등록부보다 위에 둡니다.
- 새 기능의 `Reset`, 입력, `Update`, `Draw` 호출이 빠지지 않았는지 확인합니다.
- 배경만 보이면 `OnDraw` 등록, 카메라 위치, 크기 0 여부부터 확인합니다.
- 3D가 겹쳐 보이면 깊이 검사와 깊이 버퍼 초기화를 확인합니다.
- 너무 빠르거나 PC마다 속도가 다르면 초당 속도에 `dt`를 곱했는지 확인합니다.
- 경계, 중복 클릭, 정지 후 재개, 초기화를 각각 한 번 실행합니다.
- 시험 PC에서도 미리 빌드해 라이브러리 경로와 DLL을 확인합니다.

## 로컬 검사와 재생성

```powershell
# 이 폴더에서 실행
python .\make_kit.py
.\build-check.ps1 -Number 19 -RunChecks
.\build-check.ps1 -RunChecks
```

`--check` 실행은 주요 로직 검사를 수행하고 숨김 OpenGL 창에서 8프레임을 그린 뒤 API 오류와 배경색 이외의 픽셀 존재를 확인합니다. 실제 마우스 조작감이나 화면 외관 전체를 판정하는 검사는 아닙니다. 검사에 성공한 예제도 문제 조건을 수정한 뒤에는 다시 실행합니다.
